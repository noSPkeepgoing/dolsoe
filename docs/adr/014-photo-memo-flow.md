# ADR-014: 내 한 컷 — 사진·메모는 보낸 뒤 버튼으로 초안을 고르고, 사진은 디스크·메모는 본문에 둔다

- 날짜: 2026-10-23 · 상태: 채택됨 (PRD §11 REQ-034·035; ADR-005 사다리 ③의 입력 확장)

## 맥락
사용자가 사진·한 줄 메모를 보내면 글의 "내 한 컷"에 넣는다. 승인 대기 초안이 최대 3개라 어느 글인지 정해야 한다(결정 C: 보낸 뒤 버튼으로 고르기). 스파이크: 사진은 클립보드 `image/png` 붙여넣기로 네이버 서버(`blogfiles.pstatic.net`)에 올라가고, HTML 안 `data:` 이미지는 버려진다.

## 결정
- **입력 분기**(handlers): ① `수정` 대기 중이고 링크 없는 텍스트 → 수정 지시 ② 링크가 있으면 링크 모드 ③ 사진 ④ 링크 없는 일반 텍스트 → 메모. 대기 초안이 없으면 안내만.
- 사진·메모는 먼저 **kv `pending_media`**(한 번에 하나, 새로 오면 교체·이전 파일 삭제)에 두고, `awaiting_approval` 초안 목록을 `attach` 콜백 버튼 + `attach_cancel`로 묻는다. 고르면 붙이고 카드를 다시 보낸다.
- **메모 = `experienceLine`**(REQ-011의 원문 포함 검사·REQ-015 ② 재사용). 붙이기는 LLM 재생성 없이 CAS(`awaiting_approval`) 조건부 본문 갱신이고, 이후 `수정`은 기존 규칙대로 이 문장을 유지한다. 다시 보내면 교체.
- **사진은 파일**(`MEDIA_DIR_DEFAULT`, `/data`는 gitignore)이고 DB `draft_photos`에 경로·mime·크기만 둔다(초안당 1장, 교체). 텔레그램 압축 사진(JPEG)만 받고 파일(document)로 온 것은 안내 후 거절. `PHOTO_MAX_BYTES` 초과 거절. 폐기·종료 상태(handed_off·published) 뒤 파일을 지우고, 기동 시 참조 없는 파일을 정리한다.
- **GPS**: 텔레그램은 압축 사진의 메타데이터를 제거하는 것으로 알려져 있어, **build 첫 단계에서 실제 사진으로 EXIF 유무를 확인**하고 남아 있을 때만 GPS 제거 단계를 넣는다(미확인 가정).
- **발행 연동**: `Post`에 `photoPath`(선택)를 더한다(발행부는 플랫폼을 모름, P3). 네이버 렌더러가 "내 한 컷" 자리에 `PHOTO_SLOT_MARKER`(HTML 주석)를 넣고, Playwright 드라이버가 HTML을 마커에서 둘로 나눠 **앞부분 붙여넣기 → 사진 `image/png` 붙여넣기 → 뒷부분 붙여넣기** 순서로 넣는다. 사진 업로드가 확인되지 않으면(`.se-image` 증가 + `data:` 아님) **저장 전 실패**(`editor_unavailable`)이며 사진 없이 저장하지 않는다(ADR-006·CONVENTIONS §6). 호출 데드라인(`DRAFT_DEADLINE_MS`)은 사진 업로드 시간을 포함해 build에서 조정한다. ④ 텔레그램 전달은 본문 뒤에 `sendPhoto`로 사진을 함께 보낸다.
- 태그(REQ-033): build 첫 스파이크로 임시저장에 태그가 남는지 확인하고, 안 되면 카드 표시로 후퇴한다.

## 이유
메모를 기존 필드로 받으면 검사·수정 경로가 그대로 재사용된다. 마커 분할은 에디터가 `data:` 이미지를 버리는 제약을 우회하는 가장 단순한 방법이다.

## 버린 대안
카드 답장(reply)으로만 부착(오부착은 없으나 사용자가 정한 C와 다름), 가장 최근 카드에 자동 부착(오부착), 사진을 DB BLOB에 저장(백업·크기), 사진 버튼의 파일 선택창 주입(UI 의존이 크고 위치 제어가 어려움), 사진 없이 저장(사람이 못 알아챌 수 있음).

## 결과/트레이드오프
링크 없는 일반 텍스트가 모두 메모 선택 버튼을 띄운다(취소 버튼으로 해소). 사진은 헤드리스 상시 운영에서의 클립보드 붙여넣기 동작을 build에서 같이 확인해야 한다.

## 스파이크 노트 (1.7a 0단계, 2026-10-23)
- 헤드리스에서도 `text/html` 클립보드 붙여넣기가 동작함을 확인(이미지 `image/png` 붙여넣기는 2026-10-21 headed 실측분 — 헤드리스는 1.7d에서 확인).
- **EXIF 확인(실사진 1장, 2026-10-23)**: 텔레그램 압축 사진(최대 960x1280 JPEG)에는 EXIF·GPS·XMP가 없다. 위치 노출 우려 없음. 단, "파일로 보내기"(document)는 원본이라 EXIF가 남을 수 있으니 봇은 `photo`만 받고 document는 거절/안내한다.

## 구현 노트 (1.7d, 2026-10-24)
- 태그(REQ-033): 임시저장 에디터에는 태그 입력칸이 없고 발행 패널에만 있어, 자동 입력은 하지 않는다. 카드의 `태그:` 줄 + 본문 맨 아래 `#태그` 줄로 확정(후퇴안 채택).
- JPEG는 `ClipboardItem`이 `image/png`만 안정적으로 받아서, 페이지 안에서 `createImageBitmap`→`OffscreenCanvas`로 PNG 변환 후 붙여넣는다. 실계정 관통(2026-10-24): 사진 업로드·위치·서식 확인 완료.
