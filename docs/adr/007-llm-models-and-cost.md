# ADR-007: 본문 Sonnet급 + 검증/분류 Haiku급, 월 1만원 상한

- 날짜: 2026-09-30 · 상태: 채택됨

## 맥락
글 품질이 저품질 회피의 핵심(P5), 하루 1~2회 호출. NFR-001(비용), REQ-011·015(창작 후기·금지 표현 검사).

## 결정
Anthropic SDK 직접 호출. 본문 생성은 Sonnet급, 금지 표현·경험 문장 보존 등 **가능한 한 코드로 하는 검증**은 기계(문자열 검사), LLM 검증이 필요한 부분만 Haiku급. 출력은 zod(`DraftBodySchema`)로 경계 검증, 실패 시 재시도 상한(`REGENERATE_MAX_RETRIES`). `llm_usage`에 월별 추정 비용을 기록하고 `MONTHLY_LLM_BUDGET_KRW` 초과 시 텔레그램 알림 후 기본 모드 생성 중지. **단가·정확한 모델 ID는 build 1.2 착수 전에 공식 문서로 재확인(미확인).**

## 이유
품질 우선 + 비용 통제. 기계 검증을 먼저 하면 LLM 호출이 줄어듦.

## 버린 대안
전부 저가 모델(초안 품질↓ → 수정 횟수↑), 프롬프트 캐싱(호출이 적어 효과 미미 — 재검토 항목).

## 구현 노트 (build 1.2, 2026-10-01)
- 모델 ID·단가 확인: 본문 `claude-sonnet-5-5`($2/$10 per MTok), 검증용 `claude-haiku-4-5`($1/$5). 단가는 계약 상수(`LLM_PRICING_USD_PER_MTOK`)에 있다.
- 금지 표현·경험 문장 보존·골격 검사는 모두 기계(문자열·구조)로 충분해서 **Haiku 검증 호출은 도입하지 않았다**(YAGNI). 필요해지면 `generate.ts` 루프에 추가.
- Sonnet 5.5는 샘플링 값·`thinking: {type:"disabled"}`·강제 `tool_choice`·prefill을 400으로 거부 → `body-generator.ts`는 보내지 않고(테스트로 고정), 사고는 기본(적응형)에 맡긴다. 사고 토큰도 `max_tokens`에 포함되므로 16,000으로 둔다.

## 구현 노트 (build 1.6, 2026-10-07) — 웹검색 후기 수집
- **도구**: 기본형 `web_search_20250305`(`max_uses: 3`). 동적 필터링형(`web_search_20260209`)은 코드 실행이 같이 돌아 토큰이 늘 수 있어 쓰지 않았다. 후기 수집 모델은 `LLM_MODEL_REVIEW`(현재 Sonnet 5.5, 본문과 분리해 둠).
- **단가**: 검색 1회 $10 / 1,000건(= `WEB_SEARCH_USD_PER_REQUEST` $0.01), 토큰은 별도. `estimateCostKrw`가 `webSearchRequests`를 더하고 월 누적(`llm_usage`)에 같이 들어가 상한 가드가 그대로 적용된다.
- **실측(2026-10-07, 책 1권 《싯다르타》)**: 후기 수집 약 131원(입력 23.6K 토큰 — 검색 결과가 입력으로 들어오는 비중이 큼, 검색 2회·17초) + 본문 약 35원 = **한 편 약 167원**. 월 15편이면 약 2,500원 — 상한 1만 원 안.
- **절감 여지(미적용)**: 검색 결과가 입력 토큰 대부분이므로 `max_uses`를 2로 줄이거나 후기 수집만 Haiku 4.5($1/$5)로 바꾸면 약 절반. 한국어 의역 품질을 보고 결정(운영하며 `LLM_MODEL_REVIEW`만 바꾸면 됨).

## 결과/트레이드오프
상한 초과 시 그 달 남은 기간은 링크 모드(수동 요청)만 동작하도록 할지는 build에서 확정.
