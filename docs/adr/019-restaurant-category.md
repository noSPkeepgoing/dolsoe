# ADR-019: 맛집 카테고리 — 지도 링크+사진 최대 3장, 방문 후기 어조 허용(사실 수치는 교차 확인), 협찬 표기

- 날짜: 2026-11-01 · 상태: 채택됨 (PRD §12 REQ-036; P2 맛집 예외·ADR-005·013·014 확장)

## 맥락
맛집은 쿠팡 링크가 없어 애드포스트만 수익이고, 사용자가 **직접 방문한 곳만** 지도 링크·사진으로 보낸다(전제). 사용자는 메모 없이도 후기처럼 읽히는 글을 원했다(P2 맛집 예외, PRD §12.5). 검증 가능한 사실(주소·영업시간·메뉴명·가격·수치)을 지어내는 것은 여전히 막는다.

## 결정
- **본문 `RestaurantBodySchema`**(계약): `placeName`, `placeFacts[]`(주소·영업시간·메뉴·가격·전화, 각 `origin: user|web`), `sections[]`(후기 어조 문단+`photoIndex`), `experienceLine`(사용자 메모), `sponsored`. 모델 출력(`RestaurantBodyGenSchema`)은 **사실·협찬 여부를 쓰지 못하고** 코드가 채운다(필사 문구 quote와 같은 방식, ADR-013).
- **사실 수집(`PlaceCollector`)**: 사용자 메모의 사실이 우선, 없으면 웹검색(`web-search.ts` 공용, `PLACE_SEARCH_MAX_USES`)으로 찾아 `CROSS_CHECK_MIN_SITES`곳 이상에서 글자 그대로 같은 값만 `placeFacts`에 넣는다(ADR-013 `cross-check.ts` 재사용). 출처 URL은 DB `drafts.place_sources_json`에만. 확인 못 하면 비워 두고 카드에 "확인 못 함".
- **사실 지어내기 방지**: 생성된 본문의 숫자·가격·시간 표현이 `placeFacts`/메모에 없으면 문제로 잡아 재생성(ADR-016 합산 상한). 골든셋 C8b("웨이팅 20분, 파스타 14,000원"). **L3 체험 어미 검사(REQ-027)는 맛집에 한해 끈다**(P2 맛집 예외) — 다른 카테고리는 그대로.
- **가게명 획득**: 지도 링크(`MAP_HOST_SUFFIXES`, naver.me·kko.to는 단축 링크라 리다이렉트를 따라감)에서 **공개 페이지의 `og:title` 한 번만** 읽는다(로그인 없음, 사용자가 보낸 링크 1건당 GET 1회). 실패하거나 제목이 비면 "가게 이름을 보내주세요"로 되묻는다(EDGE-033b). **build 2.2c 첫 단계 스파이크**로 가능 여부를 확인하고, 막히면 가게명 직접 입력이 기본이 된다.
- **입력 분기**(handlers 우선순위, ADR-014 위에 얹음): ① `수정` 대기 ② `pending_restaurant`(가게 이름을 물은 직후)면 다음 메시지를 가게 정보로 ③ 지도 링크가 있으면 묻지 않고 맛집 새 글(함께 온 사진 첨부) ④ 쿠팡·YES24 링크면 링크 모드(맛집 대기는 취소) ⑤ 사진만이면 `attach` 버튼들 + `new_restaurant` 버튼 ⑥ 일반 텍스트는 메모. 앨범은 `media_group_id`로 모아(약 1.5초 디바운스) 한 번만 묻고 3장 초과분은 안내한다.
- **저장**: DB v8 — `draft_photos`를 `(draft_id, position)` 복합 키로 재구성(기존 행은 position 0), `drafts.place_sources_json`·`category_evidence_json` 추가. 상품은 `source=map_link`, `affiliate=none`인 1건(제목=가게명, url=지도 링크). 같은 가게 재방문 가능하므로 `covered_products` 중복 제외는 적용하지 않는다.
- **협찬**: 메모에 `SPONSORED_MEMO_MARKER`(협찬)가 있으면 `sponsored=true` → 렌더러가 `SPONSORED_DISCLOSURE_TEXT`를 글 위·아래에 넣고 발행 게이트(REQ-010)가 누락을 막는다. 협찬이 아닌 맛집엔 문구가 없고, 카드에 "협찬 아님으로 처리됨" 한 줄을 항상 표시해 표시 누락을 사람이 알아채게 한다.
- **발행**: `Post.photoPaths[]`와 마커 `PHOTO_SLOT:n`으로 드라이버가 사진 수만큼 앞→사진→뒤를 반복해 붙인다(ADR-014 일반화). 사진 업로드 확인 실패는 저장 전 실패(ADR-006). ④ 텔레그램 전달은 `sendMediaGroup`. 호출 데드라인은 사진당 가산(build에서 조정).
- 카드: "사진 N장 · 메모 있음/없음 · 주소/영업시간 확인됨/못 함", 메모가 없으면 "후기 어조 생성 — 방문 사실 확인 필요".

## 이유
사실만 코드가 통제하고 어조는 모델에 맡기면, 사용자의 선택(후기 어조)과 법적·신뢰 위험(없는 가격·시간)의 경계를 기계로 지킬 수 있다.

## 버린 대안
메모 필수(사용자 거절), 가게명 항상 직접 입력(입력 한 줄 증가 — 폴백으로만 유지), 웹검색으로 가게 찾기(동명 가게 오류·비용), 사진 속 내용 비전 서술(없는 사실 위험·비용), 협찬 자동 감지(오탐).

## 결과/트레이드오프
방문 여부는 봇이 확인하지 않는다(사용자 책임, PRD 가정). 사진이 여러 장이라 임시저장 시간이 늘고, 헤드리스 다중 붙여넣기는 build에서 확인한다. 단축 링크/페이지 구조가 바뀌면 가게명 읽기가 깨질 수 있어(폴백 있음) 운영 관찰 대상이다.
