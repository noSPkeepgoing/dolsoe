# ADR-012: 문체 규칙은 패턴 검사로 먼저 강제하고, 출처가 추적되는 구간만 검사에서 뺀다

- 날짜: 2026-10-23 · 상태: 채택됨 (PRD §11 REQ-027·030, §3 P2 개정)

## 맥락
P2를 "새 사실 주장을 지어내지 않는다"로 개정했고, 허용 수준 사다리(L0~L4)와 L2 경계(읽었음을 함의하는 감상 금지)를 정했다. 기존 REQ-015(금지 표현)·REQ-011(지어낸 후기 차단)이 이미 있다.

## 결정
- 1차는 **결정적 패턴 검사**: `STYLE_VIOLATION_PATTERNS`(체험 어미 `-더라`, 읽었음 함의, L4 수치+기간)와 수치 한도(느낌표 `EXCLAMATIONS_MAX`, 문단 `SENTENCES_PER_PARAGRAPH_MAX`)를 `checkQuality`가 `styleIssues`로 낸다. 걸리면 금지 표현과 같게 **1회 자동 재생성, 남으면 카드에 개수 표시(차단 안 함)**. 지어낸 후기 패턴(REQ-011)은 기존대로 차단한다.
- **검사 제외는 "출처가 추적되는 구간"만**: `experienceLine`(사용자 메모)과 `quote.text`. 인용문은 생성 시 출처 텍스트에 글자 그대로 있는지 검증된 것만 남으므로(ADR-013), 수정 재생성에서는 **이전 인용문과 글자 그대로 같거나 null일 때만** 제외한다. 달라졌으면 제외하지 않고 거절·재시도.
- 카드 한 줄: `문체 점검 · 금지 표현 N개 · 경험 있음/없음`(+ 가전은 스펙 출처, 책은 후기·필사 출처).
- **LLM 분류기(L 단계 판정)는 후속**: 패턴이 못 잡는 문장을 골든셋(부록 B) 정확도로 검증한 뒤 경고 전용(차단 안 함)으로 얹는다. 1차에 넣지 않는다.
- 프롬프트 규칙은 골든셋을 few-shot으로 쓰고, 회귀 테스트는 부록 B의 허용/금지 문장을 그대로 검사 함수에 넣는다.

## 이유
기계 검사가 먼저다. LLM 분류는 비용·비결정성이 있어 골든셋 정확도를 확인하기 전엔 경고로도 신뢰하기 어렵다. 제외 범위를 "추적되는 구간 + 글자 일치"로 좁혀야 LLM이 인용처럼 꾸민 문장이 빠져나가지 못한다.

## 버린 대안
LLM 판정을 생성 루프 안에서 차단에 사용(비용·오탐), 인용 블록 전체를 무조건 검사 제외(위장 문장 통과), 사용자 원문만 제외(추천사·책 속 문장이 오탐).

## 결과/트레이드오프
정규식은 오탐·미탐이 있다. 운영하며 목록을 승격하고(CONVENTIONS §6 학습 루프), "-더라" 계열처럼 사용자 말투에서 자연스러운 표현도 봇 문장에서는 금지된다.
