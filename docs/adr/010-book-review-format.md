# ADR-010: 책 글을 한 권 깊이 리뷰형(B3)으로, 후기는 웹검색 의역

- 날짜: 2026-10-07 · 상태: 채택됨 (REQ-002 책 골격 B2 큐레이션형을 대체)

## 맥락
기존 책 글(B2)은 여러 권을 한 줄씩 소개해 상품 정보 나열에 가까웠다. 줄거리·분위기·인상 깊은 대목까지 담은, 사람이 쓴 듯한 글을 원한다. 그러나 YES24 API는 소개문·목차·작가 정보만 주고 리뷰·한줄평·미리보기·인용 엔드포인트가 없다. REQ-011(봇이 지어낸 후기·경험 금지)은 유지한다.

## 결정
1. **글 단위**: 한 권당 한 편(B3). 구성 = 제목 → 줄거리 → 분위기·읽는 느낌 → 이런 사람에게 → 인상 깊은 대목 → 구매 링크 → 내 경험 한 줄.
2. **말투**: 대화체·구어체. 지어낸 1인칭 독서 경험은 금지(REQ-011 유지) — 개인 감상은 내가 `수정`으로 준 경험 한 줄에서만.
3. **근거 수집(REQ-016)**: Anthropic 웹검색으로 독자 후기·서평을 모아 의역 근거로만 쓴다. 직접 인용·원문 문장 금지, 후기 작성자의 1인칭 경험을 내 것처럼 쓰는 것 금지.
4. **출처**: 발행 본문에는 표기하지 않고, URL은 초안 DB(`drafts`)에만 보관해 수정 때 검증할 수 있게 한다. 카드에는 "후기 N건 참고"만.
5. **인상 깊은 대목**: 책 원문 인용이 아니라 후기·소개문에서 확인된 대목을 의역해 서술한다. 원문 문장은 내가 수정하며 직접 넣는다.
6. 수집 실패 시 소개문·목차·작가 정보만으로 작성하고 "후기 근거 없음"을 표시한다.

## 이유
- 진짜 후기가 인상 깊은 대목의 유일한 근거다(API에 본문 없음). LLM이 혼자 쓰면 지어낸 인용이 된다.
- 의역·재구성은 아이디어·사실만 가져오므로 저작권 위험이 낮다.
- 출처를 본문에 안 쓰는 대신 DB에 남겨 검증 가능성을 지킨다.

## 버린 대안
- **YES24 후기 페이지 크롤링**: 약관이 크롤링·스크래핑·캐싱을 금지하고 robots.txt가 후기 목록(`GoodsReviewList`·`communityModules`)을 막는다. 애드온(해제 불가) 계정의 이용 제한·환수 위험이 수익원을 위협한다.
- 소개문·목차만 사용: 안전하나 인상 깊은 대목 근거가 약해 수정 부담이 커진다.
- LLM이 인용문 창작: 지어낸 인용(REQ-011 위반 소지·신뢰 문제).

## 결과/트레이드오프
- 웹검색 호출로 비용이 늘어난다 — ADR-007 비용 추적에 포함하고 월 상한 가드를 그대로 적용한다.
- 검색된 후기 품질이 들쑥날쑥하다 — 품질 검사에 직접 인용·URL·원문 근접 문장 검출을 추가한다.
- **미확인**: 웹검색 도구의 모델·단가·한국어 후기 수집 품질은 build 착수 시 확인(ADR-007 갱신).
- **책 소개문 길이**: 소개문 그대로 옮기는 문장 검출 임계값 N은 build에서 정한다.
