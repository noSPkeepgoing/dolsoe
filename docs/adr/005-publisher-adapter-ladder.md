# ADR-005: Publisher 어댑터 + Orchestrator 폴백 사다리, 첫 구현은 텔레그램 전달

- 날짜: 2026-09-30 · 상태: 채택됨

## 맥락
네이버 글쓰기 API의 2026년 현재 동작이 미확인(PRD Q1). 자료가 엇갈리고, 임시저장은 API 근거가 없음. 블로그 미개설. P3(발행부 분리), REQ-012·013.

## 결정
`Publisher` 인터페이스 `publish(post): PublishResult`(`mode: live|private|manual`, `retryable`, `authExpired`). 사다리(①live ②private ③manual)는 어댑터가 아니라 `PublishOrchestrator`가 우선순위 목록으로 순회하며 시도 로그를 남기고 알림에 처리 방식을 표시. **1차 구현은 ③ `TelegramHandoffPublisher`**(완성 본문을 텔레그램으로 전달, 내가 복붙). `NaverApiPublisher`는 블로그 개설 후 **스파이크(실호출 확인)** 결과에 따라 추가. 본문은 플랫폼 중립 구조체로 저장하고 렌더러는 어댑터 쪽. 대가성 문구 삽입·차단(REQ-010)은 어댑터 앞 공통 게이트.

## 이유
Q1 결과와 무관하게 구조가 안 바뀌고, ③만으로도 MVP 가치(승인 흐름·품질 검증)가 성립.

## 버린 대안
브라우저 자동화(약관·계정 정지 위험), 네이버 API 전제로 설계(미확인 리스크).

## 결과/트레이드오프
API가 안 되면 승인 뒤 복붙 한 단계가 사람 몫.

## 개정 (2026-10-17): 브라우저 임시저장 모드 추가
사용자 보고: 네이버 글쓰기 API는 현재 제공되지 않음(팀원도 브라우저 방식으로 운영). 이에 사다리를 보강한다.
- 모드에 `draft` 추가: 전용 브라우저 프로필(Playwright, 헤드풀)로 블로그 에디터에 제목·본문을 채우고 **임시저장까지만** 한다. 공개는 사람이 네이버 앱·웹에서 확인 후 누른다. 사다리: ①`draft`(브라우저 임시저장) → ③`manual`(텔레그램 전달). API 기반 ①live ②private는 API가 되살아날 때까지 보류.
- 로그인은 사람이 전용 프로필 창에서 직접 1회. 비밀번호는 저장하지 않고 세션 쿠키만 프로필에 남김(NFR-003). 평소 쓰는 Chrome 프로필은 쓰지 않음.
- 실패(선택자 불일치·세션 만료·캡차)는 조용히 넘기지 않는다: `authExpired`/실패로 보고하고 ③으로 폴백, 텔레그램에 사유 알림. 브라우저 단계가 불확실하게 끝나면 재시도 없이 `failed`(ADR-006).
- "버린 대안: 브라우저 자동화" 판단을 뒤집는다. 근거: API 부재로 대안이 없고, 임시저장까지만 하면 사람 확인이 한 번 더 남아 계정 위험이 낮다. 약관 회색지대 위험은 남음(수익 계정 — 사용자가 인지·수용).
- 트레이드오프: 에디터 화면 변경에 취약, 세션 만료 시 사람 개입 필요, 맥북에어가 켜져 있고 로그인 상태여야 함.
