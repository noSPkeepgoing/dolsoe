# ADR-013: 웹 교차 확인 — 필사 문구(책)와 스펙(가전)은 서로 다른 사이트 2곳에서 글자 그대로 확인된 것만 쓴다

- 날짜: 2026-10-23 · 상태: 채택됨 (PRD §11 REQ-028·029; ADR-010의 후기 수집기와 같은 서버 도구 웹검색)

## 맥락
필사 문구는 모델 기억에서 꺼내면 틀린 인용이 된다. 가전 링크 모드는 스펙이 비어 있다(ADR-008: 쿠팡 페이지는 긁지 않음). 둘 다 "확인된 사실만"이 필요하다. 웹검색 응답에는 모델 요약과 별개로 페이지 원문 발췌(`cited_text`)와 URL이 온다.

## 결정
- **`crossCheck(candidate, evidence[])` 순수 함수**(`src/draft/cross-check.ts`): 후보 문자열을 정규화(공백·따옴표·말줄임 정리)해 **서로 다른 호스트 `CROSS_CHECK_MIN_SITES`곳 이상**의 원문 발췌에 포함돼 있는지 센다. 통과한 후보만 쓰고, 통과 못 하면 버린다. 필사 문구와 가전 스펙이 같은 함수를 쓴다(DRY).
- 수집기는 `ReviewCollector`와 같은 모양의 어댑터 둘: `QuoteCollector`(책 제목·저자로 "독자가 많이 인용한 문장" 검색, `QUOTE_SEARCH_MAX_USES`), `SpecCollector`(상품명으로 제조사 스펙 검색, 상품당 `SPEC_SEARCH_MAX_USES`). 모델 출력은 후보와 근거 URL 목록이고 **판정은 코드가 한다**.
- 우선순위: ① 사용자 문구·스펙 ② 웹 교차 확인 ③ 소개문의 문장(추천사는 "— 이름(직함)", 그 밖은 "— 『제목』 소개글 중"으로 출처 표기, 소제목 "이 책 속 한 줄") ④ 코너·판단 생략. 소개문은 이미 가져온 데이터라 검색이 없다.
- 길이는 `QUOTE_MAX_CHARS` 이하 1~2문장. 출처 URL은 `quoteSources`·`specSources`로 **DB에만**(후기와 같은 규칙), 카드에는 개수만.
- **가전 근거 팩트**(`src/draft/facts.ts`, 순수): 상품 스펙의 숫자를 파싱해 비교값(용량 1위, 리터당 가격 최저 등)과 가구 수 매핑 표를 계산한다. 모델은 팩트 목록만 받고, 추천 문장은 `factIds`로 가리켜야 하며 존재하지 않는 ID나 팩트에 없는 수치는 검증에서 거절한다. 추측 표지("같아요/겠어요/라면/저라면")가 없는 적합성 문장은 `styleIssues`로 잡는다.
- 링크 모드의 스펙 입력: `링크 / 상품명 / 가격 / 용량 3.5L`처럼 슬래시로 구분한 `키 값` 토큰을 `specs`에 넣는다(`link-parser` 확장).
- **수정(REQ-008)** 재생성은 다시 수집하지 않고 이전 인용문·스펙을 유지한다(ADR-010의 후기와 같은 규칙).

## 이유
판정을 코드에 두면 모델의 환각이 통과하지 못하고, 수용기준이 그대로 테스트가 된다.

## 버린 대안
모델이 후보를 쓰고 스스로 확인(자기 채점), 단일 사이트 확인(오기 통과), YES24·쿠팡 페이지 직접 읽기(약관·robots), 외부 스펙 DB 연동(범위 확대).

## 결과/트레이드오프
인기 적은 책·스펙이 드문 제품은 코너·판단이 비는 날이 있다(의도된 동작). 검색 호출이 늘어 NFR-001(월 1만원)에 영향 — build 첫 실측으로 상한(`*_SEARCH_MAX_USES`)을 조정한다. 짧은 인용은 출처를 밝히면 저작권법상 허용 범위로 보지만 법률 자문은 아니다.
