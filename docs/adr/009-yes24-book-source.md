# ADR-009: 도서 소스를 알라딘에서 YES24 Open API로 교체

- 날짜: 2026-10-01 · 상태: 채택됨 (ADR-008의 도서 소스 부분을 대체)

## 맥락
알라딘 OpenAPI는 신규 키 발급이 2026-09-04에 중단되고 기존 이용자도 2026-10-30에 종료된다(공식 공지). 처음부터 시작하는 이 프로젝트는 키를 받을 수 없다. 카카오 책 검색은 검색 전용(베스트셀러·판매순 없음), 네이버 책 검색은 API Hub 이관 시 제외됐다는 보고(미확인). REQ-005·006, P5.

## 결정
도서 소스 = **YES24 Open API**(`https://apis.yes24.com`, 헤더 `X-Api-Key`, 키는 YES24 계정으로 즉시 발급·무료). 기본 모드는 `/v1/category/bestseller`·`/v1/category/newproduct`로 주제 후보를, `/v1/goods/itemList`·`itemDetail`로 상품 정보를 가져온다. 구매 링크는 응답의 `addOnLink`(애드온 신청 시 채워짐)를 쓰고 `link`(수익 미연결)는 쓰지 않는다. 호출 한도(초당 5회·일 5,000회)는 하루 1편에 충분하나 429·`Retry-After`를 처리한다.

## 이유
베스트셀러 자동 선정과 수익 연결 링크를 한 API로 얻는다. 어댑터(`ProductSource`) 뒤에 격리해 약관·응답이 바뀌어도 교체 가능.

## 버린 대안
카카오 책 검색(리스트 없음, 테마 큐 필요), 웹 크롤링(약관 위험), 알라딘(불가).

## 구현 노트 (build 1.2, 2026-10-01)
- 응답 구조·오류 코드는 공식 샘플 저장소(yes24-AX/yes24-openapi-samples)의 OpenAPI 명세에서 확인했다. 봉투 `{success, message, data:{meta, items[]}}`, 항목에 `adultYn`·`itemStatus`가 있어 성인물·판매중 아님을 어댑터가 거른다. 404 `BEST_001`(결과 없음)은 오류가 아니라 빈 목록.
- 가짜 키로 실제 서버를 호출해 `AUTH_002`(401)가 문서대로 오고 어댑터가 올바르게 해석함을 확인했다. 정상 응답(실제 키)은 미확인.
- **`addOnLink`가 비어 있는 상품은 후보에서 뺀다**(수익 연결이 이 프로젝트의 목적). 공식 데모 데이터는 `link`·`addOnLink`·`cover`가 비어 있으므로, 애드온을 신청하기 전에는 후보가 0건이 되어 "새로 쓸 상품 부족" 알림이 온다.

## 결과/트레이드오프
- **미확인(사용자 확인 필요)**: 애드온 수수료율, 대가성 문구 표기 의무, 자동화·대량 게시 금지 여부, 응답 JSON 필드 상세(실호출 전까지는 공식 샘플 기반 추정 — 필드명은 어댑터 경계의 zod가 검증해 어긋나면 즉시 드러남).
- **애드온은 한번 신청하면 해제 불가** — 정책 확인 후 신청.
- 도서는 정가제라 수수료가 낮을 가능성 → 책 카테고리 수익성은 약하다고 가정.

## 정정 (2026-10-07, 실호출 확인)
- 베스트셀러 목록·`itemDetail` 모두 `contentDetail`을 준다(추가 호출 불필요). 실제 필드는 `bookIntroduction`(소개문)·`bookSummary`(관측한 4건 모두 null)·`tableOfContents`(목차)뿐이고, **"작가 정보"는 없다** — 저자는 기존 `author` 문자열(스펙 `저자`)만 쓴다. 소개문이 빈 책도 있다.
- 소개문·목차에는 `<b>` 같은 HTML 태그가 섞이고 목차는 4,500자 이상도 온다 → 태그·엔티티·여분 공백을 걷고 `BOOK_DETAIL_MAX_CHARS`(1,500)로 자른다.
- `/v1/category/bestseller`는 **`categoryId` 필수**(없으면 400 `PARAM_001`) — 1.2 가짜 응답 테스트가 놓쳐 `fix:`로 수정. 후보는 소설/시/희곡(`001001046`)·에세이(`001001047`)만 쓴다(종합 베스트셀러엔 시험서·문제집이 섞임, ADR-010).
