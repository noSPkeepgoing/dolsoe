# ADR-020: 자동 발행 — 단계 A(배지)만 확정, 단계 B(봇이 공개)는 스파이크와 별도 승인 선행. 예약 발행 폐기

- 날짜: 2026-11-01 · 상태: 채택됨 (PRD §12 REQ-024·025; ADR-005 개정 대상)

## 맥락
ADR-005는 "임시저장까지만 자동, 공개는 사람"이라는 전제로 브라우저 자동화의 계정 위험을 받아들였다. 자동 발행(REQ-024 B)은 이 전제를 뒤집는다. 예약 발행(REQ-025)은 사용자가 "여러 편 미리 승인" 필요였으나 `발행` 즉시 처리로 이미 충족되어 폐기했다.

## 결정
- **단계 A(확정)**: `autoBadge` 순수 함수로 카드에 "자동 발행 기준 충족" 한 줄(ADR-015). 동작 불변, 버튼 하나로 승인.
- **단계 B(조건부)**: build 2.3의 **스파이크만** 먼저 한다 — `scripts/spike/naver-publish.ts`(headed, **비공개 설정 테스트 글만**, 실제 공개 글 없음)로 ① 에디터 발행 패널에서 공개 범위·카테고리·태그 입력 ② 발행 버튼 클릭과 결과 확인(비공개로) ③ 세션·셀렉터 안정성을 확인해 `docs/adr`에 가능/불가·위험·후퇴안을 기록한다. 스파이크 결과가 REQ-033(태그를 임시저장에 남길 수 없었던 문제)에 도움이 되는지도 함께 본다. **가능해 보여도** 사용자에게 계정 위험과 P1 개정(§3 P1, §5.3 "검수 없는 자동 발행")을 **별도 승인 관문**으로 다시 받기 전에는 구현하지 않는다.
- 켤 때의 최소 조건(승인 시 확정): 기본 OFF·카테고리별 켬, 폐기 1회·금지 표현·발행 실패 시 자동 해제+알림, 수동 킬스위치 명령, 카드·로그에 "자동 발행됨" 표지. 맛집 등 경험 필수 글은 대상에서 제외.
- **REQ-025 예약 발행 폐기**: `scheduled` 상태·예약 잡은 만들지 않는다. 승인 대기 상한(MAX_PENDING_DRAFTS=3)·P4 불변.

## 이유
계정 위험이 불확실한 자동화는 가능 여부(스파이크)와 책임 판단(사용자 승인)을 구현보다 앞에 둔다. 배지는 비용 없이 승인 부담을 줄인다.

## 버린 대안
스파이크 없이 단계 B 구현, 예약 발행(`scheduled` 상태·재개 로직), 예약 시각에 알림 재전송(필요 없음).

## 결과/트레이드오프
단계 B는 폐기될 수 있다. 그 경우 2.3은 배지로 끝난다.
