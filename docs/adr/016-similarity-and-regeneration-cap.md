# ADR-016: 고급 품질 검사 — 로컬 유사도·시작 어절 반복 + 모든 검사 합산 재생성 상한 2회

- 날짜: 2026-11-01 · 상태: 채택됨 (PRD §12 REQ-026; ADR-012의 "검사별 1회 재생성"을 대체)

## 맥락
금지 표현·문체·카테고리 금지 표현에 유사도·반복까지 더하면 검사마다 1회씩 재생성이 쌓여 본문 생성 비용(NFR-001)과 "고치면 다른 검사에 걸림" 문제가 생긴다. 임베딩·웹 비교는 비용·인프라가 크다.

## 결정
- **순수 모듈 `draft/similarity.ts`**(외부 호출 0): ① 본문을 문장으로 나눠 공백·문장부호 정규화 → 새 글의 각 문장이 **과거 같은 카테고리 초안 한 편**의 어떤 문장과 같거나 문자 3-gram 자카드 ≥ `SENTENCE_NEAR_JACCARD`이면 "일치". **일치 문장 비율**을 초안별로 구해 **가장 큰 값**이 `SIMILARITY_SENTENCE_RATIO_MAX` 이상이면 걸림(여러 편 혼합으로 부풀지 않게 편별 최댓값). ② **같은 첫 어절로 시작하는 문장 비율** ≥ `SENTENCE_START_REPEAT_RATIO_MAX`면 걸림.
- **제외 구간**: 사용자 메모(`experienceLine`), 필사 인용 블록, 상품명·표 수치, **템플릿 고정 문구**(소제목·코너 이름·대가성/협찬 문구·링크 안내). 렌더러가 쓰는 고정 문구 목록을 한 곳(`TEMPLATE_FIXED_PHRASES`)에서 내보내 검사와 렌더러가 같은 출처를 쓴다.
- **비교 대상**: 상태 `awaiting_approval/handed_off/published`, 같은 카테고리, 최근 `SIMILARITY_CORPUS_MAX`편. `SIMILARITY_CORPUS_MIN`편 미만이면 검사 생략(EDGE-029). 사람이 고친 최종본은 모른다(봇이 만든 본문만).
- **합산 재생성 상한**: `REGENERATE_TOTAL_MAX`(=2). 생성 루프는 검사 결과를 **하나의 문제 목록**으로 합쳐(금지 표현·문체·카테고리 금지·REQ-011 지어낸 후기·유사도·반복) 문제가 있으면 목록 전체를 프롬프트에 되먹여 재생성하고, 상한에서 남은 문제는 차단하지 않고 카드에 표시한다. 기존 `REGENERATE_MAX_RETRIES`는 이 값으로 대체되며 build 2.1에서 상수 사용처를 바꾼다.
- 임계값(0.5/0.5/0.8)은 시작값이다. 골든셋 C1~C3 회귀로 고정하고 운영하며 조정한다.

## 이유
한 번에 모든 문제를 알려 주면 "고치다 다른 것에 걸리는" 왕복이 줄어 상한 2회로 충분하다. 편별 최댓값은 "여러 글을 조금씩 짜깁기"한 오탐을 막는다.

## 버린 대안
임베딩 유사도(비용·인프라), 웹 비교(검색 비용·범위), 검사별 1회 유지(최악 비용 5배), 상한 없는 루프(예산 폭주).

## 결과/트레이드오프
글당 본문 생성 최악 3배(예산 가드가 막음). 같은 템플릿이라 문장 구조가 비슷한 가전 글은 시작 어절 반복에 자주 걸릴 수 있어 임계값 조정이 필요할 수 있다.
