# ADR-017: 검색 트렌드 — 네이버 데이터랩 상대 추이로 책 후보 순위·가전 주제 제안만

- 날짜: 2026-11-01 · 상태: 채택됨 (PRD §12 REQ-020)

## 맥락
데이터랩 검색어 트렌드 API는 **한 요청 안의 상대값(0~100)**만 주고 요청당 키워드 그룹 5개 제한이 있다. 뜨는 키워드를 알려 주지 않는다. 책 제목은 검색량이 거의 없어 0점 동점이 흔할 수 있다.

## 결정
- **역할 한정**: ① 책 기본 모드 — YES24 후보를 점수순으로 정렬해 고른다. ② 가전 날 후보 없음 — 건너뜀 알림에 **시드 키워드**(`TREND_APPLIANCE_SEEDS`) 중 상위 `TREND_SUGGEST_COUNT`개와 "링크를 보내주세요"를 덧붙인다(최근 `TREND_SUGGEST_COOLDOWN_DAYS`일 제안한 주제·30일 내 다룬 상품 키워드는 제외). 트렌드는 글·상품을 직접 고르지 않는다.
- **비교 방식**: 후보 키워드 그룹과 **공통 기준 키워드 1개**(예: "책 추천")를 같은 요청에 넣어 `점수 = 후보 비율 ÷ 기준 비율`로 정규화한다. 요청당 그룹 상한(`TREND_BOOK_BATCH_MAX`=5) 중 1개가 기준어라 묶음당 후보는 4개다. 후보가 더 많으면 같은 기준어를 넣고 묶음을 나눠 요청한다. 서로 다른 요청의 원점수는 직접 비교하지 않는다. 전부 0점/동점이면 기존 순서 유지.
- **설정/실패**: 키(`NAVER_DATALAB_CLIENT_ID/SECRET`)가 **없으면 기능 꺼짐**(`trend_days`에 기록 안 함). 키가 있는데 호출 실패·전부 0점이면 `trend_days(used=false, reason)`를 남기고 진행 — 건별 알림은 없고 주간 리포트에 "트렌드 미사용 N일"(ADR-015).
- 조회 기간 `TREND_WINDOW_DAYS`일(일 단위), 모듈 `trend/datalab.ts`(HTTP 어댑터)와 `trend/rank.ts`(순수: 점수 정규화·정렬·제안 선택)로 나눠 가짜 응답으로 테스트한다.

## 이유
상대값 한계 안에서 쓸 수 있는 가장 단순한 쓰임(순위·제안)만 택해 P5(남들과 비슷한 글 위험)와 의존도를 낮춘다.

## 버린 대안
트렌드가 주제를 직접 정함(가전은 상품 데이터 없음), 검색광고 키워드도구(광고 계정 필요), 구글 트렌드(공식 API 없음).

## 결과/트레이드오프
사용자가 데이터랩용 네이버 개발자센터 앱(Client ID/Secret)을 발급해야 실제 동작을 볼 수 있다(블로커: 2.2 실키 확인). 책 제목 점수는 약한 신호라 순위가 자주 기존 순서로 되돌아갈 수 있다.
