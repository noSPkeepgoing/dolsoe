# ADR-002: 단일 프로세스 + DB tick 스케줄 (홈서버 launchd)

- 날짜: 2026-09-30 · 상태: 채택됨

## 맥락
돌쇠는 수정 대화·재생성·발행이 모두 초안 상태에 걸려 있어 프로세스를 나누면 경합·중복 발행 위험이 커짐(REQ-009, EDGE-004). 하루 1편 규모. 실행 환경은 사용자의 맥북에어 홈서버(jipsa와 동일 운영). 관련: REQ-001, EDGE-006, P4.

## 결정
launchd(KeepAlive)가 재기동만 담당하는 **단일 Node 프로세스** 안에 봇(롱폴링)·스케줄러·발행 워커를 모듈로 둔다. 스케줄은 DB `schedule_jobs.due_at`을 **60초마다 tick**으로 확인해 실행(KST 08:00 일일 초안). 기동 시 "오늘치가 없고 시각이 지났으면 오늘치 1편만 생성 + 누락된 이전 날은 건너뛰고 '어제까지 N일 누락' 알림"(몰아서 생성 금지, EDGE-006). 외부 감시(dead-man's switch)는 도입하지 않는다.

## 이유
한 줄로 처리되니 경합이 구조적으로 없고, 예약 발행(REQ-025)은 `due_at`만 추가하면 됨. 프로세스가 죽어도 launchd가 재기동.

## 버린 대안
jipsa식 2프로세스(봇 + launchd 배치): 프로세스 간 상태 경합 방어 비용이 큼. 인프로세스 cron 라이브러리: 재기동 시 잡 유실, DB 기반 tick이 복구에 유리. 외부 dead-man's switch: 외부 의존 추가, 동작 미확인 — 필요해지면 도입.

## 구현 노트 (build 1.2, 2026-10-01)
- 기동 시(`start`): 꺼져 있던 동안 밀린 잡은 **실행하지 않고 폐기**(`claimDueJobs`)한 뒤 다음 08:00 KST 잡을 예약하고, 오늘치(시각이 지났고 오늘 시도 기록이 없을 때)만 1편 만든다. 누락 일수는 알림만.
- "시도 기록"(`kv.last_daily_attempt_date`, KST 날짜)을 **작업 실행 전에** 남긴다 → 작업 중 죽어 재기동해도 같은 날 다시 만들거나 알림이 폭주하지 않는다.
- 알림(텔레그램) 실패는 스케줄러를 죽이지 않고 로그만 남긴다.

## 결과/트레이드오프
맥북이 꺼진 동안은 어떤 알림도 못 보냄(다음 기동 시에만 알림). PRD가 수용한 결정.
