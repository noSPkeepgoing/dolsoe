# ADR-011: 글 스타일은 어댑터에만 둔다 — 본문은 의미 단위, 렌더러가 서식을 입힌다

- 날짜: 2026-10-23 · 상태: 채택됨 (PRD §11 REQ-031·032, ADR-010의 책 골격 B3를 확장)

## 맥락
블로그다운 서식(글자 크기·색·형광펜·인용구·구분선·이모지)과 카테고리별 양식을 넣는다. 스파이크(2026-10-21)로 붙여넣은 HTML의 서식 대부분이 에디터에서 유지됨을 확인했다. P3(발행부 분리)를 지켜야 한다.

## 결정
- `DraftBody`는 **의미 단위만** 담는다: 도입(`intro`)·소제목별 본문·인용(`quote`)·마무리(`closing`)·`keyword`·`tags`. 폰트·색·HTML은 LLM 출력에도 계약에도 없다.
- 서식은 `src/publish/naver-style.ts`(색·크기 토큰, 카테고리별 템플릿, 이모지 풀)와 `renderNaverHtml`이 입힌다. 책=코랄핑크, 가전=민트. 이모지는 **글 번호로 시드한 결정적 로테이션**(상태 저장 없음), 글당 `EMOJI_MAX_PER_POST` 이하를 렌더러가 지킨다.
- 계약 변경은 **추가만, 모두 optional**(`intro`·`closing`·`keyword`·`tags`·`quote`·`factIds`·`styleIssues`). 옛 저장 행이 그대로 읽히고, 렌더러·카드는 없으면 해당 코너를 뺀다. `highlights`는 필수로 유지하되 `quote`가 있으면 "이 문장이 필사하기 좋은 이유"로 쓴다. LLM 구조화 출력용 스키마는 build에서 새 필드를 required로 좁혀 따로 만든다.
- 제목 규칙(키워드 앞·이모지 없음·`TITLE_MAX_CHARS`)과 태그 개수는 `quality-check`가 검증하고, 어기면 REQ-002의 골격 문제와 같게 재시도 후 실패 처리한다.
- 대가성 문구는 작은 회색 글씨여도 `requiredDisclosures`와 임시저장 화면 검증(`mustContain`)을 그대로 지난다(REQ-010).
- 플레인 텍스트 렌더러(`renderer.ts`, ④ 텔레그램 전달·카드 미리보기)도 새 코너를 같은 순서로 낸다.

## 이유
P3: 스타일이 LLM이나 초안 쪽으로 새면 플랫폼을 바꿀 때 초안이 깨진다. 의미 단위만 두면 검증도 쉽다(HTML 이스케이프·태그 검사 불필요).

## 버린 대안
LLM이 HTML을 직접 씀(P3 위반·게이트 재검증), 본문에 스타일 필드(`color` 등) 추가(계약이 플랫폼을 앎), 에디터 고유 블록을 UI로 조작(유지보수 비용, 스파이크로 불필요함 확인).

## 결과/트레이드오프
링크가 있으면 에디터가 OG 링크 카드를 글 끝에 자동 추가한다(EDGE-021). 기본은 유지하되, build 스파이크에서 **카드 위치가 대가성 문구 앞인지**와 억제 방법(링크를 문장 속에 넣기 등)을 확인해 결정한다. 임시저장함의 실제 모양은 사람이 관통 확인한다.

## 스파이크 노트 (1.7a 0단계, 2026-10-23, `scripts/spike/naver-tags.ts`)
- **태그 입력칸(`#tag-input`)은 `발행` 패널에만 있다.** 임시저장 화면에는 없어, 임시저장만 하는 어댑터로는 태그를 넣을 수 없다(패널을 열면 곧 발행 확정 버튼과 같은 화면). 따라서 REQ-033은 **카드 표시(사람이 발행 때 입력)로 후퇴**가 기본 — "임시저장에 태그가 남는가"는 패널에 입력 후 닫아 저장해도 유지되는지 사람이 실확인해야 결론이 난다(자동으로는 발행 위험 때문에 시도하지 않음).
- **링크 카드**: 링크가 문장 속(`<p>문장 <a>…</a> 뒤</p>`)에 있을 때는 카드가 붙지 않았다(본문 3문단 그대로). 링크만 단독 문단일 때 글 끝에 카드가 붙는다는 기존 실측과 합치면, **링크는 항상 문장 속에 넣는 것으로 억제**한다.
- **헤드리스 클립보드 붙여넣기**: headed와 같은 결과(본문·링크 유지).

## 양식 보정 (1.7b, 2026-10-24, 레퍼런스 8건 분석)
- 크기는 에디터 기본 크기에 맞춘다: 본문 16, 소제목 24(옛 15·22는 에디터 목록에 없는 값이었다). 빈 줄 문단(`\u200b`)은 맨 위 대가성 문구 뒤와 책 마무리 앞에만 둔다 — 구분선 앞뒤에 넣었더니 에디터 구분선 여백과 겹쳐 섹션 사이가 과하게 벌어졌다(실측).
- 책: 맨 위 인용구(`intro`) → 도서 정보 표(제목·저자·가격) → 줄거리 → 분위기 → 이런 사람에게 → 인상 깊은 대목. 가전: 번호형 소제목 1~3 → 총평 인용구(`closing`). 소제목 이모지는 의미별 후보에서 글 번호로 고른다.
- 태그는 임시저장에 안 남을 수 있어(스파이크) 본문 맨 아래에 `#태그` 줄로도 넣는다(레퍼런스 대부분의 관행). 대가성 문구 바로 위.
- 대가성 문구는 위·아래 두 곳, 13px #495057. 링크 카드 억제(문장 속 링크)는 유지한다 — 카드 노출 여부는 사용자 결정 대기.
- 레퍼런스를 따르지 않는 것: 체험담 문체(P2), 흰 배경 흰 글자 숨김 키워드, 소제목 인용구 스타일(붙여넣기로는 기본 인용구만 나옴 — 스파이크 후속).

## 시각 재설계 (1.7b, 2026-10-24)
채도 높은 컬러 소제목·소제목마다 이모지·섹션마다 구분선·굵은 검은 표 테두리가 "촌스럽다"는 평가를 받아 절제하는 방향으로 다시 설계했다.
- 위계는 색이 아니라 크기·굵기: 소제목은 20px 진한 굵은 글씨 + 위에 13px 액센트 번호(`01`). 구매 링크 제목만 번호 없음. 소제목에 이모지 없음 — 이모지는 도입·마무리 문단에만.
- 색은 채도를 낮춘 더스티 로즈(책 `#b4546d`)·딥 틸(가전 `#2f8f83`)을 번호 라벨·형광펜(아주 옅은 톤)·표 머리·콜아웃·태그 줄에만 쓴다.
- 구분선은 본문↔구매 링크, 맨 끝 두 곳. 섹션 사이는 빈 줄 문단(`\u200b`).
- 표는 머리만 옅은 색조·선은 `#e5e7eb` 1px. 가전의 한 줄 결론은 색조 배경 1칸 표(콜아웃), 총평은 액센트 라벨 + 굵은 한 줄. 기본 인용구(큰 따옴표 장식)는 책의 맨 위 문장 한 곳에만 쓴다.
- 실측: 콜아웃(배경색 있는 표 셀)·표 셀 테두리·`font-size` span이 에디터 붙여넣기에서 유지됨.
