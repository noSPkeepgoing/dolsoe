# ADR-011: 글 스타일은 어댑터에만 둔다 — 본문은 의미 단위, 렌더러가 서식을 입힌다

- 날짜: 2026-10-23 · 상태: 채택됨 (PRD §11 REQ-031·032, ADR-010의 책 골격 B3를 확장)

## 맥락
블로그다운 서식(글자 크기·색·형광펜·인용구·구분선·이모지)과 카테고리별 양식을 넣는다. 스파이크(2026-10-21)로 붙여넣은 HTML의 서식 대부분이 에디터에서 유지됨을 확인했다. P3(발행부 분리)를 지켜야 한다.

## 결정
- `DraftBody`는 **의미 단위만** 담는다: 도입(`intro`)·소제목별 본문·인용(`quote`)·마무리(`closing`)·`keyword`·`tags`. 폰트·색·HTML은 LLM 출력에도 계약에도 없다.
- 서식은 `src/publish/naver-style.ts`(색·크기 토큰, 카테고리별 템플릿, 이모지 풀)와 `renderNaverHtml`이 입힌다. 책=코랄핑크, 가전=민트. 이모지는 **글 번호로 시드한 결정적 로테이션**(상태 저장 없음), 글당 `EMOJI_MAX_PER_POST` 이하를 렌더러가 지킨다.
- 계약 변경은 **추가만, 모두 optional**(`intro`·`closing`·`keyword`·`tags`·`quote`·`factIds`·`styleIssues`). 옛 저장 행이 그대로 읽히고, 렌더러·카드는 없으면 해당 코너를 뺀다. `highlights`는 필수로 유지하되 `quote`가 있으면 "이 문장이 필사하기 좋은 이유"로 쓴다. LLM 구조화 출력용 스키마는 build에서 새 필드를 required로 좁혀 따로 만든다.
- 제목 규칙(키워드 앞·이모지 없음·`TITLE_MAX_CHARS`)과 태그 개수는 `quality-check`가 검증하고, 어기면 REQ-002의 골격 문제와 같게 재시도 후 실패 처리한다.
- 대가성 문구는 작은 회색 글씨여도 `requiredDisclosures`와 임시저장 화면 검증(`mustContain`)을 그대로 지난다(REQ-010).
- 플레인 텍스트 렌더러(`renderer.ts`, ④ 텔레그램 전달·카드 미리보기)도 새 코너를 같은 순서로 낸다.

## 이유
P3: 스타일이 LLM이나 초안 쪽으로 새면 플랫폼을 바꿀 때 초안이 깨진다. 의미 단위만 두면 검증도 쉽다(HTML 이스케이프·태그 검사 불필요).

## 버린 대안
LLM이 HTML을 직접 씀(P3 위반·게이트 재검증), 본문에 스타일 필드(`color` 등) 추가(계약이 플랫폼을 앎), 에디터 고유 블록을 UI로 조작(유지보수 비용, 스파이크로 불필요함 확인).

## 결과/트레이드오프
링크가 있으면 에디터가 OG 링크 카드를 글 끝에 자동 추가한다(EDGE-021). 기본은 유지하되, build 스파이크에서 **카드 위치가 대가성 문구 앞인지**와 억제 방법(링크를 문장 속에 넣기 등)을 확인해 결정한다. 임시저장함의 실제 모양은 사람이 관통 확인한다.
