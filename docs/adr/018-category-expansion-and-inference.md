# ADR-018: 카테고리 확장 — 반려동물·개발장비·육아/캠핑은 비교표형 본문 재사용 + 상품명 키워드 추정(불확실하면 버튼)

- 날짜: 2026-11-01 · 상태: 채택됨 (PRD §12 REQ-022; ADR-008의 링크 모드 규칙 확장)

## 맥락
새 3개 카테고리는 자동 소스가 없어(쿠팡 API 최종 승인 전 — REQ-037) 링크 모드로만 만든다. 카테고리마다 본문 골격·렌더러를 따로 두면 1.7급 작업이 3번 반복된다.

## 결정
- **본문은 비교표형(G1) 하나를 재사용**: `ApplianceBodySchema.category`를 `COMPARISON_CATEGORIES` enum으로 넓히고(이름은 유지해 변경 폭을 줄임) 카테고리별로 **테마(색·소제목 이모지 풀)와 프롬프트 문구만** 다르게 한다. `CategorySchema`·`PRODUCTS_PER_DRAFT`·`DraftBodySchema` 확장은 계약의 "페이즈 2 병합 예정" 5곳을 **build 2.2a에서 한 번에** 적용한다(렌더러·카드·게이트 분기가 함께 바뀌어야 컴파일되므로 설계 단계에서는 적용하지 않음).
- **카테고리 추정(`categorize.ts`, 순수)**: 링크 줄의 상품명(여러 상품이면 전부)을 `CATEGORY_KEYWORDS`로 매칭한다. 비-가전 키워드가 **정확히 한 카테고리에만** 걸리면 그 카테고리(가전 키워드가 같이 걸려도 구체 카테고리 우선: "고양이 정수기" → 반려동물), 가전 키워드만이면 가전(버튼 없음, 기존 동작 유지), **아무것도 안 걸리거나 비-가전이 둘 이상이면 버튼**으로 묻는다. 한 메시지의 상품들이 서로 다른 카테고리로 갈라져도 버튼으로 하나를 고르게 한다. 걸린 키워드는 초안 `categoryEvidence`에 저장해 카드에 보여 준다(틀린 추정은 `폐기` 후 재전송, EDGE-033).
- **버튼 흐름**: 링크 메시지 원문을 kv `pending_category`에 두고 카테고리 4개 버튼(`pick_category`)+취소를 보낸다. 고르면 원문을 다시 파싱해 초안을 만든다(대기 중 새 링크가 오면 교체).
- **카테고리 전용 금지 표현**: `CATEGORY_BANNED_PATTERNS`(반려동물·육아·캠핑·개발장비의 안전/건강 효능/인증 단정). 합산 재생성(ADR-016)의 문제 목록에 들어가고 남으면 카드에 표시한다. 프롬프트에도 같은 규칙을 넣는다.
- 기본 모드(`CATEGORY_ROTATION`)는 책·가전 그대로다. 대가성 문구는 쿠팡 링크면 기존 문구.

## 이유
골격 재사용은 템플릿·검사·렌더러 코드를 늘리지 않고, 키워드 사전은 외부 호출 없이 결정론적이라 골든셋(C10~C15)으로 회귀 테스트가 된다.

## 버린 대안
`#말머리` 입력(사용자가 추정 방식을 택함), LLM 분류(비용·비결정), 카테고리마다 별도 본문 스키마(코드 3배), 항상 버튼(입력 한 단계 증가).

## 결과/트레이드오프
키워드 사전에 없는 새 상품은 버튼으로 한 번 더 누른다(운영하며 사전 확장 — 반복 지적은 사전으로 승격). 가전 키워드 우선순위가 바뀌면 기존 가전 링크 동작에 영향이 있으므로 사전 변경은 골든셋 C13을 통과해야 한다.
