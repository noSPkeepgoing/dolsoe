## 토폴로지 (ADR-002)
단일 Node 프로세스(launchd KeepAlive) = 봇(grammY 롱폴링) + 스케줄러(DB `due_at` 60초 tick) + 발행 워커. 저장소 SQLite 1파일(ADR-003).

```
텔레그램 ⇄ bot ─┬─ draft(생성·검증·상태머신) ─ llm ─ Anthropic
                 ├─ sources(Yes24 / CoupangLink) ─ 외부 상품 데이터
                 ├─ scheduler(tick) ─ schedule_jobs
                 └─ publish(Orchestrator → Naver / Handoff) ─ 네이버 블로그 / 텔레그램 전달
                          ↓
                       SQLite
```

### ✅ 1.4 발행부 (③ 텔레그램 전달)
- **1.3 /audit 이월 메모**: ① 대가성 게이트(`missingDisclosures`)는 현재 렌더러가 항상 문구를 붙여 사실상 불변식 점검이다 — 1.4에서 렌더러가 HTML 등으로 바뀌면 **최종 발행 산출물**에 게이트가 걸리도록 `render`를 함께 바꾼다. ② 전달 중 일부 청크만 나간 뒤 실패하면 `failed`인데 재시도 UI가 없다(REQ-013 범위 — Orchestrator 재시도·`failed` 카드 버튼 설계). ③ `pending_revision` kv 값 검증(`Number()`)은 낮은 위험으로 보류.
- REQ: **REQ-013**(자동), **REQ-012**(관통)
- `Publisher` 인터페이스, `PublishOrchestrator`(사다리·시도 로그·재시도·알림), `TelegramHandoffPublisher`, 렌더러(플랫폼 중립 본문 → 네이버용 HTML/텍스트)
- REQ-012는 실제 텔레그램·(가능하면) 네이버로 종단 관통 확인
- **구현 결과(2026-10-02)**: `Publisher.render(draft)`가 그 발행기의 최종 산출물을 만들고, 대가성 게이트(REQ-010)는 **사다리 모든 단계의 산출물**에 걸린다(이월 ① 해소 — 네이버용 HTML 렌더러는 1.5에서 `Publisher.render`로 추가). 재시도는 `retryable` 명확 실패에 한해 `PUBLISH_MAX_RETRIES`회, **발행기가 던지거나 계약에 안 맞는 결과를 주면 "불확실"로 보고 재시도·다음 단계 없이 `failed`**(ADR-006). `failed` 초안은 알림의 `다시 시도`(= `publish` 콜백 재사용)·`폐기`로 이어받는다(이월 ② 해소). 핸드오프는 통 단위로 보내 "일부만 나간 뒤 실패"면 `retryable=false`(중복 전달 방지). 알림 전송 실패는 발행 상태를 뒤집지 않고 로그로만 남긴다. 이월 ③(`pending_revision` 값 검증)은 낮은 위험으로 계속 보류.
- **1.4 /audit(2026-10-02) 반영**: M1 CAS 이후 예외 시 `publishing` 고착 방지(전체 감싸 `failed`+알림) · M2 핸드오프는 4xx 명확 거절만 재시도(네트워크 오류·5xx는 불확실) · L2 발행기 결과 `mode`가 자기 단계와 다르면 불확실. **이월 L1**: `failed` 전이와 `failOpenAttempts` 사이 크래시 시 시도 행이 열린 채 남는 감사 로그 부정확(영향 낮음, 트랜잭션화는 보류).
- **관통 검증(로컬 가짜 텔레그램 서버 + 실제 grammy·파일 SQLite)**: 긴 본문 4통 분할 전달·시도 로그 / 첫 통 서버 오류 → 1회 자동 재시도 성공(시도 2행; 이 관통은 /audit 이후 5xx를 불확실로 바꾸기 전 결과 — 현재는 4xx 거절만 재시도) / 재시도도 실패 → `failed` + 버튼 → 복구 후 `다시 시도`로 `handed_off` / `publishing` 고착 → 기동 복구로 `failed` + 확인 요청. **실제 텔레그램에서의 REQ-012 ③ 관통과 ①②(네이버 API)는 미실시**(키·블로그 필요).
