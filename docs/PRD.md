# PRD — 돌쇠 (dolsoe · 텔레그램 승인형 블로그 수익화 자동화)

- 문서 버전: v0.1 (초안) · 최종 수정: 2026-09-30 · 상태: **승인됨 (2026-09-30)**
- 승인 관문: 이 문서가 승인되어야 `/architect` 단계로 진입 가능

## 1. 한 줄 정의
> 텔레그램 봇이 하루 1편 블로그 글 초안을 만들어 보내면, 사람이 버튼으로 승인해 네이버 블로그에 발행하고, 제휴·광고로 월 10만원 수익을 노리는 1인용 자동화 도구.

## 2. 누가 · 무엇을 위해 · 무엇을 한다
- **누가**: 본인 1인 운영 (블로그·수익화 경험 없음, 전부 처음부터)
- **무엇을 위해**: 블로그 제휴(쿠팡파트너스) + 광고(네이버 애드포스트)로 **월 10만원** 수익. 운영 부담은 하루 몇 분 수준으로 유지.
- **무엇을 한다**:
  1. **기본 모드**: 매일 정해진 시각에 상품 데이터(쿠팡·YES24 등)에서 주제를 뽑아 글 초안 생성
  2. **링크 모드**: 내가 상품/책 링크(+메모)를 텔레그램으로 보내면 그 글을 즉시 초안화
  3. 초안이 텔레그램으로 오면 `발행 / 수정 / 폐기` 버튼으로 승인 → 네이버 블로그 발행

## 3. 핵심 설계 원칙 (이걸 어기면 실패한다)
- **P1. 사람이 승인한다.** 초기에는 자동 발행 없음. 초안 품질이 검증되면 자동화 수준을 올리는 것은 나중 결정.
- **P2. 새 사실 주장을 지어내지 않는다.** (개정 2026-10-21, §11) 봇은 사용·체험·성능·품질에 대한 **검증 가능한 사실 주장**("써봤더니", "3주 썼는데", "소음이 작아요")을 만들지 않는다. 그 아래 단계의 사람 같은 문체(독자 상황 프레임·감상·취향·가정형 1인칭)는 허용한다. 사용자가 준 메모·사진은 그대로 쓴다. 가격·재고는 단정하지 않고 기준일을 표기하고 링크로 유도. 허용 수준은 §11의 사다리(L0~L4)로 판정한다.
- **P3. 발행부를 분리한다.** 글 생성·승인 흐름은 특정 블로그 플랫폼을 몰라야 한다(네이버 → 자체 사이트 등 교체 가능).
- **P4. 지속 가능한 부담.** 하루 승인 부담을 작게(하루 1편). 승인을 미루면 자동화가 무너지므로 밀리면 멈춘다(몰아 만들지 않음).
- **P5. 정책을 지킨다.** 제휴 대가성 문구 필수, 저품질 판정(대량·복붙·AI 티) 회피.

## 4. 페르소나 & 대표 시나리오
- **아침 승인**: 아침에 텔레그램에 "오늘의 초안: 20평대 공기청정기 3종 비교"가 온다. 훑어보고 내가 써본 경험 한 줄을 넣어 `발행`을 누른다. 몇 분 안에 끝.
- **링크 모드**: 마트에서 본 밥솥이 궁금해 쿠팡 링크와 "6인용, 신혼 부부용"이라고 메모를 보낸다. 잠시 뒤 비교표형 초안이 온다.
- **밀린 날**: 이틀간 승인을 못 했다. 초안이 3개 쌓이자 봇이 새 초안 생성을 멈추고 알려준다. 밀린 글을 몰아서 만들지 않는다.

## 5. 범위
### 5.1 페이즈 1 (MVP) — "초안 생성 → 텔레그램 승인 → 네이버 발행"이 하루 1편 끝까지 돈다
- 카테고리 2개: **생활가전·주방**(글 스타일 G1 비교표형), **책 추천**(글 스타일 B3 한 권 리뷰형 — ADR-010으로 B2에서 변경), 하루 1편씩 번갈아
- 기본 모드(상품 데이터 기반 주제 선정) + 링크 모드
- 텔레그램 승인 흐름, 네이버 블로그 발행, 대가성 문구 자동 삽입
### 5.2 페이즈 2 — 이후
- 검색 트렌드 기반 주제 선정, 카테고리 확장(개발장비·반려동물·육아/캠핑·맛집), 주간 성과 리포트, ~~자체 정적 사이트 병행~~(폐기, §12.5), 자동화 수준 상향(자동 발행)
### 5.3 명시적 비범위 (Out of Scope)
- 검수 없는 자동 발행 (P1 단계)
- 발행한 글의 삭제/비공개 되돌리기 (EDGE-010, 수용)
- 봇이 꺼진 날의 밀린 글 몰아서 생성 (EDGE-006, 수용)
- 후기·경험담 창작(맛집 예외: §12.5), 방문하지 않은 곳의 맛집 글 자동 작성
- 다중 사용자(내 계정 외)

## 6. 기능 요구사항 (REQ)
> 백엔드 전체가 대상이며 UI는 텔레그램 대화뿐이라 모두 `(자동)`(기본). 화면 UI가 없으므로 `(관통)`은 실제 텔레그램·네이버로 돌려보는 종단 확인에 한정한다.

### A. 초안 생성 (기본 모드)
- **REQ-001** (P1)(자동) 매일 KST 정해진 시각에 카테고리(가전·주방 / 책)를 번갈아 하루 1편의 초안 생성을 트리거한다. 번갈아는 **자동 소스가 있는 카테고리 안에서만** 한다(소스가 하나뿐이면 매일 그 카테고리 — build 1.2에서 바로잡음: 소스 없는 카테고리 차례에 갇히면 다른 카테고리가 영영 안 나옴).
  - 번갈아 순서는 **기본 모드가 마지막으로 만든 초안의 카테고리** 기준이다. 건너뛴 날(REQ-004·005)과 링크 모드 글은 순서에 영향을 주지 않는다.
  - 수용기준: **주어진** 기본 모드가 마지막으로 가전 초안을 만들었을 때, **했을 때** 오늘 스케줄이 돌면, **그러면** 책 카테고리 초안을 1개 만든다.
- **REQ-002** (P1)(자동) 초안은 카테고리별 골격을 따른다. 가전·주방=G1 비교표형(제목→한 줄 결론→비교표→누구에게 어떤 제품→구매 링크→내 경험 한 줄), 책=B3 한 권 리뷰형(제목→줄거리→분위기·읽는 느낌→이런 사람에게→인상 깊은 대목→구매 링크→내 경험 한 줄). 여러 권 큐레이션(B2)은 폐기(ADR-010). 말투는 대화체·구어체로 사람이 쓴 것처럼 쓰되, 봇이 지어낸 1인칭 독서 경험은 쓰지 않는다(REQ-011).
  - 수용기준: **주어진** 가전 상품 3개 데이터가 있을 때, **했을 때** 초안을 만들면, **그러면** 비교표·한 줄 결론·구매 링크·내 경험 한 줄 자리가 모두 들어 있다.
  - 수용기준(책): **주어진** 책 1권의 소개문·목차·작가 정보가 있을 때, **했을 때** 초안을 만들면, **그러면** 줄거리·분위기·추천 대상·인상 깊은 대목·구매 링크가 모두 들어 있고 책 1권만 다룬다. 소개문을 그대로 옮긴 문장(길이 N자 이상 연속 일치)이 있으면 품질 검사가 잡는다.
- **REQ-003** (P1)(자동) 이미 다룬 상품/책은 N일간 다시 주제로 뽑지 않는다.
  - 수용기준: **주어진** 최근 N일 안에 다룬 상품일 때, **했을 때** 주제를 뽑으면, **그러면** 그 상품은 후보에서 제외된다.
- **REQ-004** (P1)(자동) 승인 대기 초안이 3개 이상이면 기본 모드의 새 초안 생성을 멈추고 알린다. 링크 모드(REQ-006)는 이 상한에서 예외다(내가 직접 요청한 글은 항상 만든다).
  - 수용기준: **주어진** 대기 초안 3개, **했을 때** 스케줄이 돌면, **그러면** 새 초안 없이 "대기 3개, 생성 중단" 알림만 온다.
- **REQ-005** (P1)(자동) 상품 데이터를 못 가져오면(API 실패·빈 결과) 그날 초안은 건너뛰고 알린다. **쿠팡파트너스 API가 신규 계정에 막혀 있으면** 기본 모드는 YES24 도서 데이터(베스트셀러·신상품)만 쓰고, 가전·주방은 링크 모드(REQ-006)로 시작한다(MVP로 인정).
  - 수용기준: **주어진** 상품 API가 실패할 때, **했을 때** 스케줄이 돌면, **그러면** 초안 없이 실패 알림이 오고 다음 날 정상 스케줄이 이어진다.
- **REQ-016** (P1)(자동) 책 초안은 웹검색으로 모은 독자 후기·서평을 근거로 쓴다(ADR-010). 후기 문장은 **의역만** 하고 직접 인용(큰따옴표)·원문 그대로의 문장은 쓰지 않으며, 후기 작성자의 1인칭 경험을 내 경험처럼 쓰지 않는다. 출처 URL은 **초안 DB에만** 저장하고 발행 본문에는 넣지 않는다(초안 카드에는 "후기 N건 참고"만). YES24 페이지 크롤링은 하지 않는다(약관·robots).
  - 후기를 못 모으면(검색 실패·0건) 소개문·목차·작가 정보만으로 쓰되 카드에 "후기 근거 없음"을 표시한다(초안 자체는 막지 않는다 — REQ-005와 별개).
  - 수용기준 1: **주어진** 후기 3건이 수집됐을 때, **했을 때** 초안을 만들면, **그러면** 본문에 큰따옴표 직접 인용과 URL이 없고 출처는 DB에 저장되며 카드에 "후기 3건 참고"가 보인다.
  - 수용기준 2: **주어진** 후기 수집이 실패했을 때, **했을 때** 초안을 만들면, **그러면** 초안은 만들어지고 카드에 "후기 근거 없음"이 표시된다.

### B. 링크 모드
- **REQ-006** (P1)(자동) 내가 상품/책 링크(+메모)를 보내면 스케줄과 무관하게 즉시 초안을 만든다.
  - 수용기준: **주어진** 지원되는 상품 링크와 메모, **했을 때** 텔레그램으로 보내면, **그러면** 해당 상품 기준의 초안이 승인 요청으로 온다. 지원하지 않는 링크면 안내 메시지만 온다.

### C. 승인 흐름
- **REQ-007** (P1)(자동) 초안을 텔레그램으로 보내고 `발행 / 수정 / 폐기` 버튼을 제공한다. `발행`은 누른 즉시 발행한다(예약 발행은 REQ-025, P2).
  - 수용기준: **주어진** 승인 대기 초안, **했을 때** 텔레그램 메시지를 확인하면, **그러면** 본문 미리보기와 `발행 / 수정 / 폐기` 버튼 3개가 함께 보인다.
- **REQ-008** (P1)(자동) `수정`은 내 자연어 지시로 초안을 다시 만든다. `폐기`는 초안을 버린다(기록만 남김).
  - 수용기준: **주어진** 초안, **했을 때** `수정` 후 "표를 더 간단히"라고 답하면, **그러면** 수정된 초안이 다시 승인 요청으로 온다.
- **REQ-009** (P1)(자동) `발행` 버튼을 여러 번 눌러도 한 번만 발행된다.
  - 수용기준: **주어진** 발행 대기 초안, **했을 때** `발행`을 두 번 누르면, **그러면** 네이버에는 글이 1개만 생긴다.
- **REQ-010** (P1)(자동) 제휴 링크가 있는 글에는 대가성 문구를 자동 삽입하고, 문구가 없으면 발행을 막는다.
  - 수용기준: **주어진** 제휴 링크 포함 초안, **했을 때** 발행하면, **그러면** 본문에 대가성 문구가 있고, 문구를 제거한 초안은 발행이 거부된다.
- **REQ-011** (P1)(자동) 초안에 봇이 창작한 후기·경험 문장이 들어가지 않는다. 경험은 "내 경험 한 줄" 자리에 내가 넣은 것만 쓴다(선택 사항). 가격은 단정하지 않고 기준일을 표기한다.
  - 경험 한 줄은 별도 버튼 없이 `수정`(REQ-008)의 자연어 지시로 넣는다(결정: 버튼 4개 대신 3개 유지). 재생성 결과에 **내가 준 경험 문장이 원문 그대로 포함되는지 검사**하고, 없거나 바뀌었으면 1회 자동 재시도 후 실패 알림. 그 문장 외에 봇이 만든 후기·경험 표현(예: "써봤더니")이 새로 생기지 않았는지도 검사한다. 책 글의 "사람 같은 말투"(REQ-002)는 문체일 뿐이며 이 금지를 풀지 않는다.
  - 수용기준 1: **주어진** 내 경험 한 줄이 비어 있을 때, **했을 때** 발행하면, **그러면** 경험 문단만 빠진 채 발행되고 글에는 "경험 있음/없음"이 기록된다(성과 비교용).
  - 수용기준 2: **주어진** 초안, **했을 때** `수정`으로 "경험 한 줄: 소음이 생각보다 컸어요"를 주면, **그러면** 재생성된 본문에 그 문장이 원문 그대로 들어 있다. 바뀌었다면 재시도하고, 그래도 안 되면 실패 알림이 온다.

- **REQ-015** (P1)(자동) 초안 생성 후 **최소 품질 검사**를 기계로 돌리고 결과를 초안 카드에 한 줄로 표시한다. 검사 항목은 ① 금지 표현 목록("~에 대해 알아보겠습니다" 등 뻔한 AI 문구) 포함 여부와 개수, ② 경험 한 줄 유무. 금지 표현이 있으면 1회 자동 재생성하고, 그래도 남으면 개수를 표시한 채 승인 요청으로 보낸다(차단하지 않음, 판단은 내가). 유사도·문장 구조 반복 검사는 P2(REQ-026).
  - 수용기준: **주어진** 금지 표현 2개가 들어간 초안이 생성될 때, **했을 때** 검사를 돌리면, **그러면** 자동 재생성이 1회 일어나고, 그래도 남으면 카드에 "금지 표현 N개 · 경험 있음/없음"이 표시된 채 승인 요청으로 온다.

### D. 발행 (네이버 블로그)
- **REQ-012** (P1)(자동)(관통) 승인된 초안을 네이버 블로그에 발행한다. 발행부는 플랫폼별 어댑터로 분리한다. 실제 네이버 계정으로의 발행은 유닛테스트로 검증되지 않으므로 실환경 관통 확인을 함께 한다.
  - **발행 폴백 사다리** (네이버 API 동작 여부가 미확인이라 MVP 인정 범위를 미리 정한다): ① API로 즉시 발행 → ② 안 되면 API로 **비공개 등록** 후 내가 네이버에서 공개 전환 → ③ API가 아예 안 되면 완성된 본문을 텔레그램으로 전달해 내가 복붙 발행. ②·③ 모두 MVP로 인정한다(승인 흐름·초안 품질 검증이 핵심 가치). (개정 2026-10-17·ADR-005: API가 제공되지 않아 ③ **브라우저 임시저장**을 채택했다. 발행 자체는 사람이 직접 하며 봇은 임시저장까지만 한다.)
  - 수용기준: **주어진** API 즉시 발행이 불가할 때, **했을 때** 승인하면, **그러면** 사다리의 다음 단계 방식으로 전달되고 어떤 방식으로 처리됐는지 알림에 표시된다.
- **REQ-013** (P1)(자동) 발행 실패 시 초안을 보존하고 1회 재시도, 그래도 실패하면 알린다. 인증 만료면 "재인증 필요"를 명시한다.
  - 수용기준: **주어진** 네이버가 실패를 반환할 때, **했을 때** 발행하면, **그러면** 1회 재시도 후 실패 알림이 오고 초안은 그대로 남아 있다.

### E. 보안

## 11. 페이즈 1.7 — 글 스타일 (블로그다운 서식 · 사람 같은 문체 · 내 한 컷)
> 2026-10-21 기능 추가 kickoff. 기존 REQ-002·011·015·016과 P2를 아래 내용으로 **개정·확장**한다. 뼈대(누가/무엇을 위해)는 그대로다. 스파이크 실측(2026-10-21): 붙여넣은 HTML의 글자 크기·색·형광펜·굵게/기울임/밑줄·가운데 정렬·`<blockquote>`(에디터 인용구 블록)·`<hr>`(구분선)·표(헤더 배경색)·이모지·목록은 유지되고, 이미지는 클립보드 `image/png` 붙여넣기로 네이버 서버에 업로드된다. `<img src="data:">`는 버려지고, 링크가 있으면 에디터가 OG 링크 카드를 글 끝에 자동 추가한다.

### 11.1 원칙 개정과 허용 수준 사다리
- **P2 개정**: 위 §3 P2 참고. 지어내는 것의 경계는 "검증 가능한 사실 주장인가"다.
- **P3 유지**: 폰트 크기·색·HTML은 `renderNaverHtml`(어댑터)에서만 정한다. 초안 본문(`DraftBody`)은 소제목·인용·구분선·강조 같은 **의미 단위**만 담고, LLM이 HTML·스타일을 직접 쓰지 않는다.
- **P5 유지**: 같은 양식·같은 이모지의 반복이 "템플릿 글" 신호가 되지 않게 한다.

| 단계 | 내용 | 예시 | 허용 |
|---|---|---|---|
| L0 | 정보 전달 문체 | "이 책은 ~를 다룹니다" | 허용 |
| L1 | 독자 상황 프레임 | "하루가 길었던 날엔 짧은 문장이 필요한 것 같아요" | 허용 |
| L2 | 감상·취향 표현 (후기 근거는 의역). **취향·가치만 허용, 읽었음을 함의하는 표현은 금지** | "저는 잔잔한 에세이가 좋아요" | **책의 상한** |
| 근거 판단 | 데이터에서 계산한 비교·추측·가정형 1인칭 | "1인가구라면 A가 딱 맞을 것 같아요", "저라면 C부터 볼래요" | **가전의 상한** |
| L3 | 일상 장면 연출(지난 일 서술) | "주말 아침에 커피 옆에 두고 펼쳤어요" | 봇은 쓰지 않음, 사용자 메모로만 |
| L4 | 검증 가능한 사용 주장 | "3주 썼는데 소음이 컸어요", "저희집에 쏙 들어가더라구요" | 봇은 쓰지 않음, 사용자 메모로만 |

- **L2 경계(결정, 2026-10-23, critic 반영)**: 제휴 글의 1인칭 감상이 "읽어본 사람의 추천"으로 읽히면 추천·보증 표시 규정 위험이 있으므로, 취향·가치 표현("저는 잔잔한 에세이가 좋아요", "이런 책 한 권 옆에 두면 마음이 놓일 것 같아요")만 허용하고 읽었음을 함의하는 표현("이 대목이 와닿았어요", "울컥했어요", "읽으면서 ~했어요", "저한테 하는 말이기도 해요")은 금지한다. 인용구 아래 한 줄은 감상이 아니라 **문장 자체에 대한 설명**("필사하기 좋은 이유")으로 쓴다. 이 위험은 대가성 문구(REQ-010)로 사라지지 않는다.
- 일기체는 **혼잣말 어조와 현재의 감정·생각**만 쓴다. 지난 일을 서술하는 문장은 쓰지 않는다. 말투는 처음부터 끝까지 부드러운 해요체다(결정).

### 11.2 REQ
- **REQ-027** (P1)(자동) 문체 규칙. 책은 L2 이하, 가전은 근거 판단 이하로만 쓴다. 지난 일 서술·체험 어미("~더라고요/~더라구요", "써보니", "놓아보니", "들어갔어요" 등 겪은 일·사용 사실을 단정하는 표현)와 L4 신호(수치+기간, 결함·성능 단정)는 금지한다. 해요체, 문단당 3문장 이하, 느낌표는 글당 3개 이하, 초성 표현(ㅋㅋ·ㅠㅠ) 금지. 책 글은 L2 경계(§11.1)대로 읽었음을 함의하는 감상 표현도 금지 표현에 포함한다. "지난 일 서술" 판정은 과거형 서술 패턴 검사와 LLM 분류(부록 B 골든셋으로 회귀 테스트)를 함께 쓴다. REQ-002의 말투 문장과 REQ-011의 "봇이 창작한 경험 금지"를 이 규칙으로 대체한다(경험 한 줄은 사용자가 준 것만 쓰는 점은 유지).
  - 수용기준: **주어진** 책 초안이 "퇴근길에 읽었더니 눈물이 났어요"를 포함할 때, **했을 때** 문체 검사를 돌리면, **그러면** 금지로 판정되어 1회 자동 재생성되고, 그래도 남으면 카드에 표시된다.
- **REQ-028** (P1)(자동) 가전 근거 판단. 판단에 쓰는 스펙의 출처는 ① 사용자가 링크 줄에 적은 스펙(예: `에어프라이어 A / 59000 / 용량 3.5L`)이 **우선**, ② 없으면 웹검색으로 찾되 **서로 다른 사이트 2곳 이상**에서 같은 값으로 확인된 항목만 채운다(출처 URL은 DB에만, 쿠팡 페이지는 읽지 않음 — ADR-008). ③ 확인되지 않은 항목은 판단하지 않는다. 코드가 글에 들어간 제품끼리만 비교 계산해 **근거 팩트**(용량 1위, 리터당 가격 최저 등)를 만들고, LLM은 이를 문장으로 풀어 쓴다. 판단 문장은 근거 팩트의 수치 한 줄과 함께 나오고, 적합성 판단에는 추측 표지("~같아요 / ~겠어요 / ~라면 / 저라면")가 붙는다. 가구 수 적합성은 코드의 매핑 표로 정한다. 데이터에 없는 항목(소음·내구성 등)은 판단하지 않는다. 카드에는 스펙 출처 구분("직접 입력 / 웹 확인 N건 / 확인 못 함")을 표시한다.
  - 수용기준 1: **주어진** 용량 3.5L·5L·12L와 가격 3개(사용자 입력), **했을 때** 초안을 만들면, **그러면** 리터당 가격이 표에 계산되어 있고 "1인가구라면 3.5L가 맞을 것 같아요" 같은 추측형 문장이 수치와 함께 나오며, "소음이 작아요"는 없다.
  - 수용기준 2: **주어진** 가격만 입력되고 웹에서 용량이 2곳 이상 확인되지 않을 때, **했을 때** 초안을 만들면, **그러면** 용량 판단 문장이 없고 가격 근거 판단만 있으며 카드에 "스펙 확인 못 함"이 표시된다.
- **REQ-029** (P1)(자동) 책 필사 문구. 인용구 블록 문구는 아래 **우선순위**로 고르며, 어느 경우에도 가져온 데이터·검색 결과·사용자 메모에 **글자 그대로 존재하는** 1~2문장(약 100자 이내)만 쓰고 모델 기억에서 꺼낸 문장은 쓰지 않는다. ① 사용자가 보낸 문구 ② 웹검색(ADR-010 수집기 확장)의 원문 발췌에서 **서로 다른 사이트 2곳 이상**에 글자 그대로 있는 문장(출처는 "— 『책 제목』, 저자", 사이트 URL은 DB에만) ③ 소개문의 문장(추천사는 "— 이름(직함)", 그 밖은 "— 『책 제목』 소개글 중"으로 출처를 정직하게 표기하고 소제목을 "이 책 속 한 줄"로 바꿈) ④ 모두 없으면 코너를 빼고 카드에 "문구를 보내주시면 넣을게요"를 표시. 이 인용 블록은 소개문 복붙 검사(REQ-002)의 예외이고 후기 직접 인용 금지(REQ-016)는 유지한다. YES24 페이지 크롤링은 하지 않는다. 검색 추가 비용은 NFR-001 범위 안이어야 하며 build에서 측정한다.
  - 수용기준 1: **주어진** 웹 원문 발췌 2곳에 같은 문장이 있고 1곳에만 있는 문장도 있을 때, **했을 때** 초안을 만들면, **그러면** 2곳 이상에 있는 문장만 인용되고 "— 『제목』, 저자"가 붙는다.
  - 수용기준 2: **주어진** 웹 교차 확인 후보가 없고 소개문에 추천사 문장이 있을 때, **했을 때** 초안을 만들면, **그러면** 그 문장이 "— 이름(직함)"으로 출처가 표기돼 들어간다. 후보가 모두 없으면 코너가 없고 카드에 요청 문구가 보인다.
- **REQ-030** (P1)(자동) 문체 점검을 REQ-015에 확장한다. 금지 표현에 REQ-027의 체험 어미·L4 신호를 더하고, 카드에 "문체 점검 · 금지 표현 N개 · 경험 있음/없음" 한 줄을 표시한다. **출처가 추적되는 구간**(사용자 메모, REQ-029 인용 블록)은 검사 대상이 아니다. 단 그 구간이 원본과 **글자 그대로 같을 때만** 제외하고, 달라졌으면 검사 대상으로 되돌린다.
  - 수용기준: **주어진** 사용자 메모에 "써봤더니 소음이 컸어요"가 있을 때, **했을 때** 검사를 돌리면, **그러면** 메모는 금지 표현으로 잡히지 않는다. 같은 글에서 인용 블록이 원본(출처 텍스트)과 달라졌다면 제외되지 않고 검사에서 잡힌다.
- **REQ-031** (P1)(자동)(관통) 카테고리별 양식. `renderNaverHtml`이 책(코랄핑크)·가전(민트) 템플릿을 적용한다. 본문은 진회색 16 크기, 소제목 24(에디터 기본 크기, 레퍼런스 분석 2026-10-24), 형광펜은 섹션당 1곳·글당 3곳 이하, 한 줄 감상·결론은 인용구 블록, 섹션 사이는 구분선, 가전 비교표는 헤더 색 채움, 책·가전 모두 "내 한 컷" 코너는 사용자 메모·사진이 있을 때만. 이모지는 소제목 앞 1개와 도입·마무리 1~2개, 글당 8개 이내이며 소제목 이모지는 풀에서 돌려 쓴다. 대가성 문구는 **글 맨 위(제목 바로 아래)와 맨 아래 두 곳**에 13px 진회색(숨김 처리 없음)으로 넣고 **발행 게이트(REQ-010)와 임시저장 화면 검증을 그대로 통과**해야 한다. 임시저장함의 실제 모양은 사람이 관통 확인한다.
  - 수용기준: **주어진** 책 초안, **했을 때** HTML을 만들면, **그러면** 책 템플릿 순서(도입→어떤 책→읽는 느낌→이런 사람에게→필사하고 싶은 한 줄→내 한 컷(있을 때)→구매 링크→대가성 문구)로 렌더링되고 이모지는 8개 이하다.
  - 수용기준(가전): **주어진** 가전 초안과 쿠팡 대가성 문구, **했을 때** HTML을 만들면, **그러면** 가전 템플릿 순서(한 줄 결론 인용구→한 줄 소개→비교표(헤더 색 채움)→이런 사람에게→내 한 컷(있을 때)→구매 링크→대가성 문구)로 렌더링되고, 대가성 문구가 REQ-010 게이트와 화면 검증을 통과하며, 형광펜이 섹션당 1곳 이하다.
- **REQ-032** (P1)(자동) 제목·태그 SEO. 제목은 핵심 키워드(상품·책·카테고리)를 앞에 두고 25자 안팎, 키워드 1회, **이모지·장식 특수문자 없음**으로 만든다. 태그는 관련어 5개 내외(상품명·책 제목·저자·카테고리·주제어)를 만든다. 키워드는 **데이터에 있는 확실한 단어**(상품명·카테고리·책 제목·저자)만 쓰고, 검색량 근거는 없다(결정). 네이버가 공식 확인하지 않은 통념에 근거한 것이므로 지표(조회·유입)로 검증하며, 검색량 기반 키워드는 REQ-020(P2, 트렌드 기반 주제 선정) 때 함께 다룬다.
  - 수용기준: **주어진** 에어프라이어 3종 비교 초안, **했을 때** 제목과 태그를 만들면, **그러면** 제목이 "에어프라이어 추천 3종 비교…"처럼 키워드로 시작하고 25자 안팎이며 이모지가 없고, 태그가 5개 안팎이다.
- **REQ-033** (P1)(자동)(관통) 태그 전달. 태그를 초안 카드에 보여주고, 임시저장할 때 에디터에 자동 입력한다(결정: 스파이크 전제). **build 첫 단계 스파이크**로 임시저장에 태그가 남는지 확인하고, 안 되면 카드 표시만으로 후퇴한다(사람이 발행할 때 붙임).
  - 수용기준: **주어진** 태그 5개가 있는 초안, **했을 때** 임시저장하면, **그러면** 임시저장함에서 태그가 확인되거나, 스파이크가 실패한 경우 카드에 태그 목록이 복사 가능한 형태로 표시된다.
- **REQ-034** (P1)(자동) 내 한 컷 입력. 텔레그램으로 사진 또는 텍스트 메모를 보내면(입력 분기 우선순위: ① `수정` 대기 상태면 수정 지시(REQ-008) ② 링크가 있으면 링크 모드(REQ-006) ③ 사진 ④ 링크 없는 일반 텍스트는 메모) 봇이 "어느 글에 붙일까요?"를 **대기 초안 버튼**으로 묻고, 선택한 초안에 붙인다. 메모는 기존 `experienceLine`을 재사용하고(REQ-011의 원문 포함 검사 유지), 사진은 글당 1장이고 메모도 글당 1개이며, **다시 보내면 둘 다 교체**된다. 사진의 위치정보(GPS)는 제거하고 나머지 메타데이터는 유지한다. 폐기하면 사진도 삭제한다. 텔레그램 압축 사진만 받고 파일(HEIC 등)로 보낸 사진은 안내 후 거절한다. 붙일 대기 초안이 없으면 안내만 한다. `수정`으로 다시 만들어도 메모와 사진은 유지된다. 링크 모드(REQ-006)의 "링크+메모"는 기존대로 동작한다.
  - 수용기준: **주어진** 대기 초안 #7·#8, **했을 때** 사진을 보내고 #8을 고르면, **그러면** #8에만 사진이 붙고 카드에 "내 한 컷 있음"이 표시되며, 같은 초안에 다시 보내면 교체된다.
  - 수용기준 2: **주어진** `수정` 버튼을 누른 뒤 지시를 입력하는 상태, **했을 때** "표를 더 간단히"를 보내면, **그러면** 메모로 붙지 않고 수정 지시로만 처리된다. 링크가 있는 메시지는 링크 모드로 처리된다.
- **REQ-035** (P1)(자동)(관통) 사진 임시저장. 사진이 있는 초안은 클립보드 `image/png` 붙여넣기로 에디터에 올려 임시저장한다. 업로드가 확인되지 않으면 **사진 없이 저장하지 않고** 저장 전 실패로 처리해 알린다(ADR-006, 불확실하면 폴백하지 않음).
  - 수용기준: **주어진** 사진이 붙은 초안, **했을 때** 발행(임시저장)하면, **그러면** 임시저장함의 글에 사진이 네이버 서버 이미지로 들어 있다. 업로드가 실패하면 저장되지 않고 실패 알림이 온다.

## 12. 페이즈 2 — 관측 · 콘텐츠 확장 · 발행 자동화
> **상태: 승인됨 (2026-11-01)** — 다음은 `/architect`(델타만).
> 2026-11-01 기능 추가 kickoff. §6.F의 한 줄 REQ-020~026을 아래로 **상세화·개정**한다(ID 유지). 뼈대·P1~P5는 그대로이며, P1은 REQ-024 단계 B가 켜질 때만 개정한다. `prd-analyst` 사전 검토 반영. **구현 순서: 2.1 관측 → 2.2 콘텐츠 → 2.3 발행 자동화.** REQ-023(자체 정적 사이트)은 **폐기**한다(§12.5).

### 12.1 서브페이즈 2.1 — 관측 (REQ-021, REQ-026)
목적: 어느 카테고리를 더 쓸지, 승인·폐기·수정 비율이 어떤지 알고, 글 품질의 반복·유사를 잡는다. 이 지표가 REQ-024 판정의 재료다. 외부 대시보드는 긁지 않는다(약관·세션 위험).

- **REQ-021** (P2)(자동) 주간 성과 리포트. 매주 일요일 20:00 KST(가정)에 지난 월~일(KST) 주간 요약을 텔레그램으로 보낸다. 항목: ① 카테고리별 생성·승인(임시저장 `handed_off`)·폐기·건너뜀 수 ② **수정 없이 승인한 비율**과 수정 후 승인·폐기 비율(**본문 변경 지시만 "수정"으로 센다** — 경험 한 줄 입력, 메모·사진 첨부는 수정 횟수에서 뺀다) ③ 경험(메모/사진) 있는 글 비율 ④ 최근 4주 대비 증감 한 줄 ⑤ 트렌드 미사용 일수(REQ-020). **"발행 수"는 임시저장 수를 승인 수로 표기**한다(실제 공개 여부는 봇이 모른다). 수익은 자동 수집하지 않고 `/수익 <쿠팡> <애드포스트>`(원 단위 두 숫자)로 원할 때 입력해 그 주에 기록하며, 입력된 주만 리포트에 나온다. 활동이 0이어도 리포트는 "이번 주 활동 없음"으로 **반드시 나간다**(NFR-004). 리포트는 승인 대기를 만들지 않는다(P4).
  - 수용기준 1: **주어진** 한 주에 책 3편(수정 없이 승인 2·수정 후 승인 1)과 가전 1편(폐기)이 있을 때, **했을 때** 일요일 20:00이 되면, **그러면** 카테고리별 수와 "수정 없이 승인 50%" 같은 비율이 담긴 리포트가 한 통 온다.
  - 수용기준 2: **주어진** 그 주에 아무 초안도 없고 `/수익` 입력도 없을 때, **했을 때** 리포트 시각이 되면, **그러면** "이번 주 활동 없음"이 온다.
  - 수용기준 3: **주어진** `/수익 12000 3400`을 입력했을 때, **했을 때** 그 주 리포트가 나가면, **그러면** 쿠팡 12,000원·애드포스트 3,400원이 해당 주에 표시된다. 형식이 틀리면 안내만 하고 기록하지 않는다.
- **REQ-026** (P2)(자동) 고급 품질 검사. 새 초안을 **내 과거 초안 DB(폐기 제외, 승인·임시저장분 우선)**와 비교해 ① 문자 n-gram 유사도 ② 문장 시작 패턴 반복(같은 어절로 시작하는 문장 비율)을 **로컬 계산**한다(임베딩·외부 호출 없음, 비용 0원). **유사도는 문장 단위 일치율**(공백·문장부호 정규화 후 같거나 n-gram이 근접한 문장의 비율)로 정의하고 **임계값은 계약 상수로 `/architect`에서 정한다**. 기준을 넘으면 재생성하고, 그래도 넘으면 차단하지 않고 카드에 "유사도 N% · 반복 시작 N곳" 한 줄로 표시한다(REQ-015와 같은 원칙, 판단은 내가). 비교 대상에서 **출처 추적 구간(사용자 메모, REQ-029 인용 블록, 상품명·표 수치)과 템플릿 고정 문구(소제목·코너 이름·대가성 문구·링크 안내)는 제외**한다. 재생성은 REQ-015·027·022·026 검사를 **합쳐 글당 최대 N회**(계약 상수, 설계에서 결정; 기존 1회 규칙 대체)로 제한하고 상한에서 남은 문제는 카드에 표시한다(비용 NFR-001 보호). 사람이 임시저장 뒤 고친 최종본은 봇이 모르므로 비교 대상은 봇이 만든 본문이다.
  - 수용기준 1: **주어진** 과거 승인 초안과 문장 70% 이상이 일치하는 새 초안, **했을 때** 검사를 돌리면, **그러면** 재생성되고 상한 뒤에도 같으면 카드에 유사도가 표시된다(차단 안 함).
  - 수용기준 2: **주어진** 문장 10개 중 6개가 "이 책은"으로 시작하는 초안, **했을 때** 검사하면, **그러면** 반복 시작이 표시되고 재생성된다.
  - 수용기준 3: **주어진** 초안이 과거 글과 사용자 메모만 같을 때, **했을 때** 검사하면, **그러면** 메모는 비교에서 빠져 유사 판정이 나지 않는다.

### 12.2 서브페이즈 2.2 — 콘텐츠 확장 (REQ-020, REQ-022, REQ-036, REQ-037)
- **REQ-020** (P2)(자동) 검색 트렌드 주제 선정. 네이버 데이터랩(검색어 트렌드) 상대 추이를 **순위 매기기와 제안**에만 쓴다. ① **책(기본 모드)**: YES24 후보 중 후보의 키워드(책 제목·저자·주제어) 추이가 높은 순으로 정렬해 고른다(REQ-003 중복 제외 후). 데이터랩 점수는 **같은 요청 안의 상대값**이므로 후보 전체를 한 요청(또는 공통 기준 키워드를 둔 묶음)으로 비교하고, 서로 다른 요청의 점수는 직접 비교하지 않는다. **전부 0점이거나 동점이면, 또는 데이터를 못 받으면 기존 순서로 그대로 진행한다**(트렌드 없이도 돈다). 트렌드를 쓰지 못한 날은 로그에 남기고 **주간 리포트(REQ-021)에 "트렌드 미사용 N일" 한 줄**로 드러낸다(NFR-004: 조용히 묻히지 않게). ② **가전(자동 소스 없음)**: 가전 날 기본 모드가 후보 없음으로 건너뛸 때, 건너뜀 알림에 **트렌드 상위 주제 3개**("에어프라이어·무선청소기·제습기 — 링크를 보내주세요")를 덧붙인다. 키워드 풀은 설정 가능한 시드 목록(가전·주방 카테고리 키워드)이다. 트렌드가 직접 글을 만들거나 상품을 고르지는 않는다. 트렌드 키워드가 최근 30일 다룬 상품과 겹치면 제외한다(REQ-003).
  - 수용기준 1: **주어진** YES24 후보 5권과 데이터랩 추이 점수, **했을 때** 책 날 초안을 만들면, **그러면** 점수가 가장 높은 후보가 선택되고 카드에 "트렌드 순위 N위"가 표시된다.
  - 수용기준 2: **주어진** 데이터랩 호출이 실패할 때, **했을 때** 책 날 초안을 만들면, **그러면** 기존 순서대로 초안이 만들어지고 건별 알림은 없으며(알림 폭주 방지) 그 주 리포트에 "트렌드 미사용 1일"이 표시된다.
  - 수용기준 3: **주어진** 가전 날 후보가 없을 때, **했을 때** 건너뜀 알림이 가면, **그러면** 알림에 트렌드 주제 3개와 "링크를 보내주세요" 안내가 들어 있다.
- **REQ-022** (P2)(자동) 링크 모드 카테고리 확장: **반려동물 · 개발장비 · 육아/캠핑**. 입력은 가전과 같은 링크 모드(쿠팡 파트너스 단축 링크 + 링크 다음 줄 `상품명 / 가격` + 메모)이고 **기본 모드(하루 1편 번갈아 REQ-001)는 책·가전 그대로**다. 카테고리는 **링크 줄의 상품명 키워드로 봇이 추정**한다(코드의 키워드 사전 매칭 — 부록 C 골든셋). 추정이 불확실하면(어느 카테고리에도 안 걸리거나 둘 이상 걸림) **카테고리 선택 버튼**으로 되묻고, 한 메시지에 여러 상품이 있어 카테고리가 갈리면 버튼으로 하나를 고르게 한다. 맛집은 상품 링크가 아니라 지도 링크·사진으로 구분한다(REQ-036). 글 양식은 가전 비교표형(근거 판단 상한)을 재사용하고 카테고리별 색·소제목만 다르다. **카테고리 전용 금지 표현**을 추가한다: 반려동물·육아는 안전성·건강/의학 효능("아이에게 안전", "관절에 좋다", "질병 예방")과 KC/인증 단정, 캠핑은 안전·방수 성능 단정. 걸리면 REQ-027과 같이 1회 재생성, 남으면 카드에 표시한다. 대가성 문구는 쿠팡이면 기존 문구를 쓴다.
  - 수용기준 1: **주어진** 상품명이 "강아지 자동급식기 A / 59000"·"고양이 정수기 B / 45000"인 쿠팡 링크 메시지, **했을 때** 처리하면, **그러면** 반려동물로 추정되어 비교표형 초안이 만들어지고 대가성 문구가 들어 있다.
  - 수용기준 2: **주어진** 초안에 "관절에 좋아요"가 있을 때, **했을 때** 검사하면, **그러면** 금지 표현으로 잡혀 재생성되고 남으면 카드에 표시된다.
  - 수용기준 3: **주어진** 어느 키워드에도 안 걸리는 상품명("멀티탭 C"), **했을 때** 처리하면, **그러면** 카테고리 선택 버튼이 오고 고른 카테고리로 초안이 만들어진다. 기존 가전 키워드("에어프라이어")는 버튼 없이 가전으로 처리된다.
- **REQ-036** (P2)(자동)(관통) 맛집 카테고리(사진+메모, 링크 모드 전용). 기본 모드에서는 만들지 않는다. 사용자가 **사진(최대 3장)과 메모**를 보내면 초안을 만든다(입력은 **지도 링크(네이버지도·카카오맵)와 사진**이 핵심이며, **메모는 선택**이다. 입력 분기는 REQ-034 우선순위에 다음을 얹는다 — ① `수정` 대기 상태면 수정 지시 ② **맛집 대기 상태(봇이 가게 이름을 물은 직후)면 다음 메시지를 가게 정보(지도 링크 또는 가게명)로 받는다** ③ 지도 링크가 있으면 **묻지 않고 맛집 새 글**(함께 온 사진은 그 글에 붙임, 앨범은 한 묶음으로 취급) ④ 쿠팡·YES24 링크면 링크 모드 ⑤ 사진만 오면 **봇이 항상 묻는다**: 대기 초안 버튼들 + **"맛집 글 새로 만들기"** 버튼 하나(대기 초안이 없어도 이 버튼은 나옴), 맛집 새 글을 고르면 가게 정보가 없으므로 "가게 이름(지도 링크)을 보내주세요"로 ②번 대기 상태에 들어간다 ⑥ 링크 없는 일반 텍스트는 메모). **메모가 있으면** 그 감상을 본문 중심으로 쓰고(REQ-011 원문 보존), **메모가 없으면 사진과 지도 링크만으로 초안을 자동 작성**하며, **맛집에 한해 방문 후기 어조(L3까지: 맛·분위기·일상 장면의 1인칭 서술)를 봇이 쓸 수 있다**(결정 2026-11-01, 아래 §12.5 P2 맛집 예외). 단 **검증 가능한 사실은 지어내지 않는다**: 주소·영업시간·메뉴명·가격·수치(대기 시간, 인원 등)는 확인된 값이나 사용자 메모에 있는 것만 쓰고, 사진에 보이지 않거나 확인 안 된 메뉴·가격을 만들지 않는다. 가게명은 지도 링크에서 얻고(단축 링크 해석 방식은 설계에서 결정), 가게명이 있으면 **주소·영업시간·메뉴·가격**을 웹검색으로 보강하되 REQ-028과 같이 **서로 다른 사이트 2곳 이상에서 같은 값**으로 확인된 항목만 쓰고 확인 안 되면 쓰지 않는다(출처 URL은 DB에만, 기준일 표기). 사진은 메모에 적힌 것 이상으로 사진 속 내용을 서술하지 않는다. 사진은 순서대로 본문에 배치하고 GPS는 제거한다(REQ-034 규칙 확장). **쿠팡 링크가 없으므로 쿠팡 대가성 문구는 넣지 않는다(내돈내산 가정 — 협찬·체험단이면 사용자가 메모로 표시해야 하며 그때 협찬 문구 필요: 설계에서 결정)**. 카드에 "사진 N장 · 메모 있음/없음 · 주소/영업시간 확인됨/못 함"을 표시하고, 메모가 없으면 "후기 어조 생성 — 방문 사실 확인 필요"를 함께 표시한다. 사진 여러 장 업로드는 REQ-035를 확장하고, 사진 1장이라도 업로드 확인이 안 되면 사진 없이 저장하지 않는다.
  - 수용기준 1: **주어진** 지도 링크와 사진 3장과 메모("김치가 맛있었음"), **했을 때** 처리하면, **그러면** 메모 기반 감상이 들어간 초안이 만들어지고 사진 3장이 순서대로 들어가며 메모에 없는 맛 묘사는 없다.
  - 수용기준 1c: **주어진** 대기 초안 #7이 있고 지도 링크 없이 사진 1장만 올 때, **했을 때** 봇이 묻는 버튼을 보면, **그러면** "#7에 붙이기"와 "맛집 글 새로 만들기"가 같이 나오고, 후자를 누르면 "가게 이름(지도 링크)을 보내주세요"가 오며, 다음 메시지는 메모가 아니라 가게 정보로 처리된다. 지도 링크가 들어 있는 메시지는 묻지 않고 맛집 새 글이 된다.
  - 수용기준 1b: **주어진** 지도 링크와 사진 2장뿐(메모 없음), **했을 때** 처리하면, **그러면** 방문 후기 어조의 초안이 만들어지되 확인되지 않은 영업시간·가격·메뉴명·수치는 없고, 카드에 "메모 없음 · 후기 어조 생성(사실 확인은 내 몫)"이 표시된다.
  - 수용기준 2: **주어진** 웹에서 영업시간이 1곳에서만 확인될 때, **했을 때** 초안을 만들면, **그러면** 영업시간은 글에 없고 카드에 "영업시간 확인 못 함"이 표시된다.
  - 수용기준 3: **주어진** 사진 4장을 보낼 때, **했을 때** 처리하면, **그러면** 4번째는 받지 않고 "최대 3장" 안내가 간다.
- **REQ-037** (P3)(자동) 쿠팡 파트너스 API 소스(`CoupangApiSource`). **최종 승인(누적 판매 15만원, 2차 자료 기준 — 공식 확인 필요) 후에만** 착수하는 후속 REQ다. 승인되면 상품 검색·카테고리 베스트·골드박스·딥링크 생성을 `ProductSource` 어댑터로 추가해 가전·신규 카테고리를 기본 모드 번갈아 순서에 참여시킨다. **이번 페이즈 범위 밖**이며 게이트 예외 목록에도 "착수 전"으로만 둔다.
  - 수용기준: 승인 전에는 해당 없음(착수 시 `/kickoff`로 상세화).

### 12.3 서브페이즈 2.3 — 발행 자동화 (REQ-024, REQ-025)
- **REQ-025** (P2) **폐기(결정, 2026-11-01)**: 예약 발행은 만들지 않는다. 사용자의 필요(여러 편을 미리 승인)는 이미 가능하다 — `발행`은 누른 즉시 임시저장되므로 몰아서 승인해도 된다. 시각 예약·`scheduled` 상태·"켜지면 즉시 실행"은 만들지 않는다(비범위). 승인 대기 상한 3(REQ-004)도 그대로다.
- **REQ-024** (P2) 자동 발행 옵션. **두 단계**로 나눈다.
  - **단계 A (확정, 자동)**: **자동 승인 추천 배지**. 카테고리별로 최근 10편 중 **수정 없이 승인 8편 이상 그리고 폐기 1편 이하**("수정" 정의는 REQ-021과 같다: 경험 한 줄·메모·사진 첨부는 수정이 아니다)이고 이번 초안이 문체 점검·REQ-026 검사를 통과하면 초안 카드에 "자동 발행 기준 충족" 배지를 단다. 경험(메모/사진)이 필수인 글(맛집 등)과 최근 10편이 안 채워진 카테고리는 대상이 아니다. 배지는 표시일 뿐 동작은 그대로이며 **버튼 하나(`발행`)로 승인**한다.
  - **단계 B (조건부, 관통)**: **봇이 네이버 에디터에서 공개 버튼까지 누르는 자동 발행**. 먼저 **스파이크**로 가능 여부를 확인한다(안 되면 단계 A만 남고 단계 B는 폐기). 가능해도 계정 정지·저품질 위험(ADR-005 개정 대상)과 P1 개정을 **별도 승인 관문**으로 사용자에게 다시 받고, 그 전에는 켜지 않는다. 켤 때의 조건은 설계에서 확정하되 최소한 ① 기본값 OFF, 카테고리별로 켬 ② 폐기 1회·금지 표현 감지·실패 시 **자동 해제**와 알림 ③ 수동 **킬스위치** 명령 ④ 자동 발행 글에는 "자동 발행됨" 표지가 카드·로그에 남음.
  - 수용기준 1(단계 A): **주어진** 가전 카테고리 최근 10편 중 수정 없이 승인 9·폐기 0이고 새 초안이 검사를 통과할 때, **했을 때** 카드를 보내면, **그러면** "자동 발행 기준 충족" 배지가 붙는다. 수정 없이 승인이 7편이면 붙지 않는다.
  - 수용기준 2(단계 B 스파이크): **주어진** 테스트용 비공개 글, **했을 때** 에디터 공개 자동화를 시도하면, **그러면** 가능/불가와 후퇴안이 ADR에 기록된다(실제 공개 글은 만들지 않음).

### 12.5 비범위·가정·분리
- **폐기**: **REQ-023 자체 정적 사이트 병행 발행**은 하지 않는다(결정 2026-11-01: 네이버 블로그만 계속 이용). 동시 발행 모델·호스팅·도메인은 만들지 않으며, 발행부는 P3 인터페이스 덕에 필요해지면 그때 새 `/kickoff`로 다시 연다. §5.2의 "자체 정적 사이트 병행"과 §6.F의 REQ-023도 이 결정으로 대체된다.
- **P2 맛집 예외 (결정 2026-11-01)**: 사용자가 **직접 방문한 곳만** 지도 링크·사진으로 보낸다는 전제에서, 맛집 카테고리에 한해 봇이 방문 후기 어조(L3)를 쓸 수 있다. 이 전제를 지키는 것은 사용자 몫이며 봇은 확인하지 않는다. 한계선은 **검증 가능한 사실(주소·영업시간·메뉴명·가격·수치)은 지어내지 않는 것**이다. 맛집 외 카테고리의 P2(L3·L4 금지)는 그대로다. §5.3의 "실제 방문이 필요한 맛집 글 자동 작성" 비범위는 "**방문하지 않은 곳의** 맛집 글 자동 작성"으로 개정한다(본 결정으로 인한 문서 개정).
- **비범위**: 예약 발행(REQ-025 폐기), 대시보드 긁기식 수익·클릭 수집, 임베딩·웹 유사도 검사, 쿠팡 API 연동(REQ-037은 승인 후), 맛집 기본 모드 자동 생성, 사진 모자이크, 트렌드로 주제·상품을 직접 선택.
- **가정(검증 안 됨)**: ① 쿠팡 API 최종 승인 조건(누적 판매 15만원)은 블로그 등 2차 자료 근거이며 공식 문서로 확인하지 않았다. ② 네이버 데이터랩이 시드 키워드 상대 추이를 안정적으로 준다(키 발급·한도는 설계에서 확인). ③ 에디터 공개 자동화 가능 여부와 계정 위험은 스파이크 전까지 모른다. ④ 맛집은 내돈내산을 가정한다. 네이버지도 단축 링크(naver.me)에서 가게명을 얻는 방법(리다이렉트 해석 가능 여부)은 설계 스파이크 전까지 모른다. ⑤ 주간 리포트는 일요일 20:00 KST로 가정했다.
